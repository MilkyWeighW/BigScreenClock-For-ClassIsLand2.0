## 1. 项目定位

一个 **ClassIsland 2.1 插件**：在教室大屏上全屏显示「时间 / 教室音量 / 课程与打铃 / 提醒与预警」，
并按课程统计教室吵闹次数。它不是独立程序，宿主是 ClassIsland（下称 CI）；插件通过
`[PluginEntrance]` 注册（`Plugin.cs:15-16`），由 CI 的 DI 容器托管生命周期。

定位上有一个明确边界：**只读 CI，不回写 CI**。主题强调色、时间偏移、天气缓存、预警、课表、
倒计时/文本组件全部是「抄一份过来用」（`Helpers/CiThemeReader.cs:10-15`、
`Helpers/ClockThemeApplier.cs:99-114`、`ViewModels/FullScreenClockViewModel.Course.cs:127-131`），
插件自身的所有状态只写进自己的配置目录 `Plugin.ConfigFolder`（`Plugin.cs:57-63`）。

1.4.0.0 是一次「补齐与稳定化」，不改定位：`README.md:60` 明说 1.4.0.0 是背景 / 组件 / 主题色 /
时间来源 / 设置页预览 / 内存治理的补齐，不新增产品方向。

## 4. 启动、生命周期与线程模型

### 4.1 启动顺序（为什么这样排）

`Plugin.Initialize`（`Plugin.cs:55-121`）是同步的，顺序有硬约束：

1. `ConfigFolder = PluginConfigFolder`（`:57`）——后面所有文件路径都基于它。
2. **同步**读 `Settings.json`（`:63`）：宿主 `Initialize` 返回前必须已有 Settings，
   因为 DI 单例、设置页、组件默认值都直接读它；异步加载会让这些路径先拿到 null
   （注释 `Plugin.cs:60-62`、`Services/SettingsStore.cs:14-16`）。
3. 运行时状态归零 `AdjustingLayout = false`（`:67`）——「正在拖滑块」不该跨会话持久化。
4. 迁移链（全部带版本号，只跑一次）：补组件布局（`:70`）→ 旧 `ShowXxx` 搬进组件启用
   （`:73`）→ **重合组件默认隐藏**（`:76`，见 01 验收反馈 3）→ 老配置有背景图则切到「自定义图片」
   （`:79-80`）→ 补默认压暗 30%（`:83`）→ 老配置主题落黑暗槽（`:90-91`，见 `Helpers/ClockThemeApplier.cs:60-67`）。
5. 壁纸磁盘缓存清理 `WallpaperCacheService.CleanupCache()`（`:86`，只留最近 6 张，见
   `Services/WallpaperCacheService.cs:160-190`）。
6. 挂 400ms 防抖存盘（`:93-102`）、注册 `ProcessExit` 同步刷盘（`:104-106`，见 01 审查修复 4）；
   之后 DI 注册（`:108-122`）。

### 4.2 常驻服务与 HostedService

| 注册 | 形态 | 说明 |
|---|---|---|
| `PluginSettings` | 单例 | 设置即单例，全插件共用一个实例（`Plugin.cs:108`） |
| `DecibelMeterService` / `CameraActivityService` / `FullScreenClockViewModel` | 单例 | `Plugin.cs:110-112` |
| `AutoTriggerService` | 单例 + HostedService（工厂取同一个实例） | 见 01 R17：以前注册了两份，hosted 那份才订阅事件，DI 解析到的是空壳（`Plugin.cs:113-120`） |
| `ServiceProviderCapture` / `TrayMenuService` | HostedService | 捕获 SP、注册托盘项（`Plugin.cs:118,120`） |

### 4.3 打开 / 收起大屏的时序

`Show()`（`ViewModels/FullScreenClockViewModel.Lifecycle.cs:46-164`）在 UI 线程一次做完：

1. 取消进行中的退出淡出；重解析 CI 时间服务与主题资源（`:50-57`，宿主可能晚于插件就绪）。
2. 把字号/开关/主题从设置搬进 VM，并 `RefreshAppearanceBindings`（`:59-70`）——
   这些是表达式 getter，窗口复用后不会自动刷新。
3. 首次创建窗口并挂 `Closed/Activated/ActualThemeVariantChanged`（`:74-95`）。
4. 重置计数、**同步**载入当天课表、纠正保护期起点（`:122-131`）。
5. 起 1s 刷新定时器、防休眠、麦克风、摄像头（`:138-142`）。
6. **先截图再显示**：`ScreenCaptureService.CapturePrimaryScreen(0.0)`（`:148`）——
   必须在窗口出现前拍，否则会把自己拍进去（`:145-147`）。
7. `PrepareForIntro()` → `WindowState=FullScreen` → `Show()` → 再落一次全屏 → `BeginBackgroundIntro`
   → 三次 `ReassertFullScreen`（0/60/320ms）（`:150-160`）。重复是给平台「晚一拍」兜底。

收起走 `Hide()`（`:279-304`）：先 `PrepareForExit` 停置顶守卫（不然淡出半秒里课表栏会闪），
整窗淡出 `480/speed` ms，然后停定时器/服务、把 CI 主界面显示回来。

### 4.4 线程模型

| 线程 | 跑什么 | 证据 |
|---|---|---|
| UI 线程（Avalonia Dispatcher） | 所有控件、窗口、动画时间线、VM 属性通知 | `FullScreenClockViewModel.Lifecycle.cs:48` 全部 `Dispatcher.UIThread.Post` |
| 线程池 | 设置序列化写盘、壁纸解码+模糊、跨天重读课表 | `Services/SettingsStore.cs:92-109`、`BackgroundLayer.axaml.cs:398-409`、`FullScreenClockViewModel.Course.cs:111` |
| 音频采样线程（NAudio/WinMM） | RMS→EMA→迟滞分级→持续判定，**不依赖 UI Timer** | `Services/DecibelMeterService.cs:22-26` |
| CI 的 MF 后台线程 | 摄像头活动回调，整体替换 `volatile` 快照，UI 侧只读引用 | `Services/CameraActivityService.cs:38-45,173-184` |
| WebView2 内部浏览器进程 | 网页渲染；控制器只允许 UI 线程发起 | `Views/WebViewHost.cs:15-19` |

关键约定：**跨线程只传不可变快照或 Post 回 UI**，没有设置锁——`PluginSettings` 只在 UI 线程改，
写盘时把引用交给线程池读（`SettingsStore` 用版本号合并，`Services/SettingsStore.cs:58-110`）。

## 5. 渲染管线

### 5.1 分层顺序（从下到上）

`Views/BackgroundLayer.axaml:9-27` 定义背景层内部的五层：
`SolidFill`（纯色底）→ `PriorImage`（旧画面/截图）→ `IntroVeil`（开屏压暗）→
`TargetImage`（壁纸或自定义图）→ `Veil`（明暗遮罩）。

`Views/ClockSurface.axaml` 决定大局：

### 5.2 透明窗口 + BackgroundLayer

窗口**永远是透明窗口**：`TransparencyLevelHint = Transparent`、`Background = Transparent`
（`Views/FullScreenClockWindow.Background.cs:36-40`）。理由写在注释里：底色不靠窗口画，
`BackgroundLayer` 一定铺一层 `BackgroundColor` 作为底，所以透明不会变成「看桌面」（`:37-39`）。

`BackgroundLayer.Apply`（`Views/BackgroundLayer.axaml.cs:101-143`）是唯一入口，按
`BackgroundKind` 分派：壁纸（`:361-391`，走 `WallpaperCacheService` 缓存加模糊）、
自定义图片（`:446-495`）、纯色（`:498-508`）、以及「自己什么都不画」的
实时模糊/网页（`:517-529`，同时把在途壁纸解码作废，防迟到结果盖住网页，`:514-516`）。

`NeedsTransparentWindow` 只在 `NativeBlur` / `WebPage` 两档为 true（`:113`）——
这是「背景层告诉窗口要不要透明」的唯一出处。

### 5.3 组件层与 ComponentHost

每个可独立调整的元素包一层 `ComponentHost`（`Views/ComponentHost.cs:13-32`），它只做四件事：

- 缩放 / 长宽比 / 位移合成**一个矩阵**（`:193-219`）：
  `Matrix.CreateScale(Scale*StretchX, Scale*StretchY) * Translation(OffsetX% × 屏宽, OffsetY% × 屏高)`；
  默认值下 `RenderTransform = null`（`:203-208`），与 1.3.1.1 逐像素一致。
- 字体：遍历 `TextBlock` 用 `SetCurrentValue` 改，**不断开绑定**，并记 `FontSnapshot` 以便还原
  （`:254-303, 317-336`）；默认值下「一个文字块都不碰」（`:221-239`）。
- 文字材质：`TextMaterialLayer` 已不是控件、不产生视觉节点，它直接改文字的字形填充
  （`:345-358`，详见 §5.4）；无材质时连这个对象都不建（`:360-365`）。
- 不透明度：直接作用在外壳上（`:180-181`）。
- 审查修复后 `Apply` 里先 `ApplyTemplate()`（`:172-186`）；「一键重置」换掉整张 `ComponentLayouts` 字典时
  会重挂新布局（`:157-166`）。

### 5.4 文字材质（作用在字形填充上）

**2026-11-15 验收反馈后重写**：用户明确要「材质作用在文字本身」，不要文字背后垫一块外框。
`Views/TextMaterialLayer.cs` 因此改成**纯逻辑类**（不是控件、没有视觉节点）：对每个 `TextBlock`
快照 `(Foreground, Effect)`，用 `SetCurrentValue` 把 `Foreground` 换成材质画刷、`Effect` 换成效果
（`:20-28`、`:151-158`）。

- 磨砂：原色纵向渐变（α 0.95→0.75）+ `BlurEffect` 半径 0.8（`:31-32, 170-172, 208-213`）；
- 液态玻璃：三段渐变（白高光 α0.55 → 原色 α0.9 → 原色 α0.7）+ 黑色半透明 `DropShadowEffect`
  （Blur 5 / OffsetY 1）（`:33-41, 173-179, 201-207`）；
- 原 `Foreground` 不是纯色的文字块跳过、不硬改（`:144-145`）；`Mode=None` / `DetachSource` 按快照还原
  （`:92-99, 226-241`）；换档位先还原再重套（`:54-65`）；换主题/文字改色时按新基准色重建（`:123-149`）；
  画刷按 `(档位, 基准色)` 缓存，布局回调里不 new（`:43-44, 186-195, 197-221`）。

边界：这是**字形填充层面的近似**（渐变 + 小半径模糊/投影），**不是逐像素折射**。
DWM 只在 `BackgroundKind.NativeBlur` 档作为底层模糊背景；材质本身**不吃背景像素**（`:13-18`）。

### 5.5 DWM 实时模糊

`Services/NativeBlur.cs` 直接 P/Invoke 未公开的 `SetWindowCompositionAttribute`
（`:51-53`，「为什么不用 CsWin32」写在 `:9-11`）。策略：先试 acrylic，失败退 blur-behind，
再失败返回 false（`:62-82`）；任何异常都当作「没有原生模糊」（`:77-81`）。
接线在窗口侧：`SyncBackgroundMode` 按档位开关，并传 `0x99000000` 的 ABGR 着色
（`Views/FullScreenClockWindow.Background.cs:81-107`）。

### 5.6 WebView2 下层窗口

WebView2 的原生子窗口天然压在同窗口的 Avalonia 内容之上（`Views/WebBackgroundWindow.axaml.cs:11-14`），
所以必须**另开一个下层窗口**：

- `WebBackgroundService`：`Attach/Sync/Detach` 三入口（`Services/WebBackgroundService.cs:14-20`），
  `Attach` 幂等——同一窗口直接返回，不再「每次 Sync 都拆掉重建 Edge 窗口」（`:46-56`）；
  250ms 跟随大屏位置/尺寸（`:245-278`），大屏隐藏 12s 后连窗口带 WebView2 一起释放
  （`:32-33, 194-243`），且隐藏计时不会被 250ms 跟随无限推迟（`:194-210`）。
- `WebViewHost`：真 HWND 承载 `CoreWebView2`，关右键菜单/DevTools/状态栏/快捷键
  （`Views/WebViewHost.cs:70-78`），默认背景透明（`:80-88`），`Dispose` 先解事件再 `Close`（`:262-289`）；
  `Bounds` 按**物理像素**设置并同步 `RasterizationScale`（`:120-142`），URL 未变不重复导航（`:177-194`）。
- **本地网页（验收反馈新增）**：`PluginSettings.BackgroundWebFile`（绝对路径，空 = 不用）；
  `ResolveNavigationUrl` 优先把它转成 `file:///`（`new Uri(fullPath).AbsoluteUri`，空格/中文正确转义），
  文件不存在/路径非法才退回网页地址（`Services/WebBackgroundService.cs:376-406`）；
  `NavigateIfNeeded` 按最终 URL 去重（`:408-426`），窗口销毁时清空去重记录（`:274-299`）。
  设置页入口在 `Settings/BackgroundExtrasPanel.axaml.cs:160-255`（选择/清除/提示，均走
  `WebBackgroundService.Active?.Sync(...)` 立刻生效）；面板里也说明了「相对资源必须与 html 同目录」
  （`BackgroundExtrasPanel.axaml.cs:120-122`）。
- **服务自订阅设置**：`WebBackgroundService.Active` 静态暴露当前实例（`:40-44`），服务自己监听
  `BackgroundKind/BackgroundWebUrl/BackgroundWebFile/BackgroundColor` 变化并重算（`:140-170`），
  不依赖调用方记得再 Sync 一次。
- 可用性探测 `WebView2Availability`：加载器 API 优先、注册表兜底、再提示缺 Loader
  （`Services/WebView2Availability.cs:62-102`），结果 `Lazy` 只算一次（`:32-37`）。

## 7. 主题与时间来源

### 7.1 两套主题档位，谁说了算

- 没开背景开关：`ThemeMode`（0 跟随 CI / 1 明亮 / 2 黑暗 / 3 自动）说了算（`Models/ClockTheme.cs:4-22`）。
- 开了背景开关：改用 `BackgroundThemeMode`（0 自动 / 1 暗底白字 / 2 亮底黑字）
  （`Models/BackgroundThemeMode.cs:11-21`），映射到同一套 `ClockThemeMode`（`:24-33`）。
  为什么两套：有背景图时底色是图，再叫「黑暗」会调出一屏白字（`BackgroundThemeMode.cs:4-9`）。

解析入口 `ClockThemeApplier.EffectiveMode`（`Helpers/ClockThemeApplier.cs:31-34`）
→ `ClockTheme.ResolveVariant`（`Models/ClockTheme.cs:178-187`）。「自动」档方向故意反直觉：
**亮图配白字**（先把背后压暗，字才立得住），暗图配黑字（`ClockTheme.cs:15-21`）；
读不出图时退化成跟随 CI（`:182-186`）。

### 7.2 颜色槽位

6 个可调颜色（背景/字体/课程信息/音量标题/进度/降水）按明亮、黑暗各存一套
（`Models/ThemeColorSet.cs:10-28`）。切主题时「先把当前这套存回旧槽、再读新槽」
（`ClockThemeApplier.cs:16-25`），所以来回切不会冲掉用户调过的色。
两个槽位是**带通知的属性**，不是自动属性——只改槽位也能触发 400ms 存盘
（`Models/PluginSettings.cs:531-552`，见 04 §R14）。

语义色（五档/预警/计数）不随主题翻转，只按底色深浅换明度版本（`Models/SemanticColors.cs:3-8`）。

### 7.3 强调色跟随

`CiThemeReader.TryReadAccentColor()` 在 UI 线程按候选资源键找强调色
（`AccentFillColorDefaultBrush`…`SystemAccentColor`，`Helpers/CiThemeReader.cs:25-32`），
命中缓存、读不到每次重试（`:36-37`），资源重建后失效（`:76-79`）。
写入设置走单向 `SyncAccent`（`ClockThemeApplier.cs:106-114`）；只有用户**没手动改过**进度条色
时才用强调色接管进度条（`ClockThemeApplier.cs:124-137`）。
订阅两条信号：`IThemeService.ThemeUpdated` 与 `Application.ResourcesChanged`
（`FullScreenClockViewModel.cs:485-544`）——后者兜住「只换强调色、没走主题切换」的情况。

### 7.4 时间来源

**全插件只有一条时间轴**：`CiTimeService.Now`。优先 `IExactTimeService.GetCurrentLocalDateTime()`
（CI 已把时间偏移算进去），服务缺失/调用失败时永久回退 `DateTime.Now` 且只记一次日志
（`Services/CiTimeService.cs:78-102`）。缓存 15ms 是为了「同一次刷新里取多次不跨服务调用，
又不让秒跳变迟滞」（`:15-17`）。

为什么要统一：以前大屏读数用本机时间、课程/打铃用 CI 虚拟时间，偏移不为 0 时读数与进度对不齐
（`CiTimeService.cs:11-13`）。现在显示时间、课程定位、打铃全用 `NowVirtual`
（`FullScreenClockViewModel.cs:186-193`、`Lifecycle.cs:333-349`），偏移为 0 时等价于 1.3.1.1。
