结果：`已成功生成。` **0 error / 11 warning**（全部为改造前既有警告），耗时约 7s；
`cipx/LargeScreenClockRevived.cipx` 2,078,218 字节；清单 `version 1.2.0.0 / apiVersion 2.1.0.0`。
`-Dev` 路径另经实测：输出五位版本（如 1.2.0.0.5）、`devbuild.txt` 递增、`-Clean` 分支正常。

静态自检（各改动方执行）：partial 文件类名/namespace 一致、成员声明无跨文件重复、原文件逐行比对 missing/extra=0、
死代码残留 0、`git diff --stat` 只落在各自写范围内。

已知注意事项：

* 构建机若在**沙箱**里运行，Avalonia 构建服务可能因无法写
  `%LOCALAPPDATA%\AvaloniaUI\BuildServices\buildtasks.log` 报 `MSB4018 UnauthorizedAccessException`；
  这是环境权限问题，不是代码错误。可在命令后加 `-p:UsedAvaloniaProducts=` 关掉该遥测 Target。
* **不要**给 `dotnet build` 传 `-p:BaseIntermediateOutputPath` / `-p:MSBuildProjectExtensionsPath`：
  实测会破坏 CsWin32 源生成，产生大量 CS0234/CS0246 假错误。
* 同一工程并发构建必须走 `build.ps1`（或手工 `Global\bsclock-build` 互斥量），否则 `obj/` 互相踩。
* 本轮**未做真机运行验证**：麦克风重启、噪音分级、预烘、摄像头检测、CI 宿主兼容性均只做了静态审查+编译验证。

## 5. 遗留与建议

1. **R5 语义（保守实现）**：`QuietThreshold` 现在只影响「安静 ↔ 良好」的**降级线**，且被夹在
   `[GoodThreshold×0.8, GoodThreshold]` 内。默认值下行为与旧版逐点一致；把「安静」调到迟滞下界
   （0.015×0.8=0.012）以上才会改变分界。若希望「安静阈值」直接决定安静档边界（低于此值即安静），
   会改变默认分级结果，需要产品层确认后再动。
2. `Models/ImageHeader.cs` 的类注释原写「认不出的格式由调用方按老窗口宽处理」，R3 后该路径已不存在，
   注释已同步更新（本轮顺手修）。
3. 首轮报告列出的 P2/P3 问题（`_inRenderPass` 之外的单线程烘焙白屏、Frosted 每帧 DrawImage、
   地震双层重采样、躲光标 CTS 不 Dispose、同名连堂丢计数等）本轮**未处理**，见 [00-总览.md](00-总览.md) §8。
4. 改动均未提交（`git status` 可见）；建议按「修复 R1-R6 / 结构拆分 / 构建脚本」三次原子提交，
   提交前如需可再跑一次 `build.ps1` 与 `build.ps1 -Dev`。
