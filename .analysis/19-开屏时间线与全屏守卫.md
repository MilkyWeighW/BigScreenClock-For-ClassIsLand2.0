# 19 · 第十六轮：全屏守卫、默认值与开屏压暗时间线（2026-11-07）

回应反馈（m03722）：

1. 调整完设置后大屏仍会「窗口化」；
2. 默认设置：下方元素边距与上方一致；
3. 默认压暗 30% 的背景；
4. 组件大小下限降到 10%；
5. 缓慢压暗背景仍然「没有动画」，且要求压暗演到约 75% 时就开始后续渲染，不要串行。

## 1. 全屏被落回窗口化

### 根因

`Views/FullScreenClockWindow.axaml.cs` 之前只在两个时机保状态：

- `Opened` 里兜底设一次 `WindowState = FullScreen`；
- `Activated` 里只重排 Z 序（把 ClassIsland 课表栏抬回上面）。

打开 ClassIsland 设置页、切到别的窗口再切回来、或系统在某些 DPI/焦点变化下，平台会把全屏窗口的
`WindowState` 落回 `Normal`，而没有任何代码再把它拉回去——于是大屏就永久停在「窗口化」状态，
直到关闭重开。截图里那种「四周露出桌面、任务栏可见」就是 `Normal` 且尺寸没回到全屏。

### 修复（两道保险）

1. **状态监听**：`PropertyChanged` 里新增分支——`WindowState == Normal` 且窗口可见时，
   用 `Dispatcher.UIThread.Post(..., DispatcherPriority.Background)` 在下一拍调
   `EnsureFullScreenState()`，等平台把 Normal 应用完再纠正，避免和平台状态来回打架
   （`_reassertPosted` 防重入）。
2. **看门狗**：新增 `_fullScreenGuardTimer`（700ms），与原有 1.5s 的置顶守卫同生命周期——
   添加/删除窗口、`Opened`、`Activated` 时都会 `EnsureFullScreenState()`；窗口不可见时两支定时器
   一起停，`PrepareForExit()` 也一起停，退出淡出期间不会强行拉全屏。

`EnsureFullScreenState()` 只处理「可见且状态既不是 FullScreen 也不是 Minimized」的情况，
用户主动最小化时不会被它弹回来。

> 本机没有 ClassIsland 宿主，窗口化场景无法复现验证，逻辑上属于「打断后立刻纠正」的兜底；
> 若真机仍偶发，需要用户补一份复现步骤（开关哪个设置、从哪个窗口切回来）。

## 2. 默认值调整

| 项 | 旧 | 新 | 位置 |
| --- | --- | --- | --- |
| 主内容区边距 | `40,30,40,18` | `40,30,40,30`（上下对称） | `Views/ClockSurface.axaml:42` |
| 背景明暗默认 | `0` | `-30`（压暗 30%） | `Models/PluginSettings.cs:52` |
| 组件缩放下限 | `0.5`（50%） | `0.1`（10%） | `Models/ComponentLayout.cs`、`Settings/SettingsPage.axaml:109` |

### 「默认压暗 30%」对老配置也要生效一次

只改字段默认值只会影响新装用户——已有 `Settings.json` 里明暗值早被序列化成 `0` 了。
所以加了一次性迁移：

- `PluginSettings.BackgroundDimMigrationVersion`（0 = 没套过，套完置 1）；
- `PluginSettings.MigrateBackgroundDimDefault()`：版本为 0 且当前明暗 `≈0` 时补成 `-30`，
  用户自己调过的非零值不动；
- `Plugin.cs` 在加载配置后调用一次（紧挨背景类型迁移）；
- `ResetAllToDefaults()` 的跳过清单加入该版本号，避免重置后下次启动又跑一遍。

所以：**老配置升级后第一次启动会自动变成压暗 30%**；一键重置也会回到 -30。

## 3. 开屏压暗：从 Transitions 改成手写时间线，并在 75% 处重叠后续渲染

### 为什么之前「没有动画」

两轮修改前压暗是靠 `Transitions` 给 `Veil` 挂 `DoubleTransition` 再改 `Opacity`。
在部分环境（尤其是 `ScaleTransform`/覆盖层刚接上视觉树时）过渡根本不 tick，表现就是硬切黑，
用户三次反馈「压暗没有动画」。此外原流程是：

```
显示压暗截图 → await Task.Delay(dimMs) → await Task.Delay(holdMs - dimMs) → 交叉淡入 → 结束
```

串行执行，总时长长，压暗演完才开始换背景，观感就是「卡一下再动」。

### 现在的做法（`Views/BackgroundLayer.axaml.cs`）

`PlayIntroAsync` 只负责铺底：`Apply` 套静态值 → 清过渡 → 三层归零 → 把「未压暗的当前屏幕截图」
垫到 `PriorImage`。然后交给 `RunIntroTimeline()`：

- 16ms `DispatcherTimer`（`DispatcherPriority.Render`）+ `Stopwatch` 手写插值，不用 Transitions；
- `revealAt = round(dimMs * 0.75)`，`total = revealAt + fadeMs`；
- `[0, revealAt)`：`IntroVeil.Opacity` 0 → 0.45，CubicEaseOut；
- 到 `revealAt`：调用 `onTargetReveal`（ClockSurface 开始淡入组件），**不等压暗演完**；
- `[revealAt, total)`：同一条时间线里同时推进
  `IntroVeil` 淡出、`PriorImage` 淡出、目标层淡入；
  壁纸类型再把 `_targetScale` 从 `zoom-0.15` 推到 `zoom`（镜头推近），自定义图只淡 `TargetImage`，
  纯色只淡 `SolidFill`；
- 结束 `CompleteIntro()` 落最终值并释放垫底截图。

时间线可被 `StopIntroTimeline()` 取消（`Apply()` 与 `PrepareForIntro()` 开头都会调），
所以中途改设置不会留下半截动画。

### 效果

压暗与换背景/组件淡入两段叠着跑：总时长从 `dimMs + hold + fadeMs` 降到
`0.75*dimMs + fadeMs`（默认速率下 210ms + 520ms），且压暗是手写插值，任何环境都会演。
