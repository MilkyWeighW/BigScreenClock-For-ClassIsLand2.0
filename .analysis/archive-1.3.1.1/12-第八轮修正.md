## 1. 景深（壁纸推近）动画不播放

### 根因

`Views/BackgroundLayer.axaml.cs` 上一版用 Avalonia 的 `Transitions` 给 `ScaleTransform.ScaleX/Y` 挂 `DoubleTransition`：

```csharp
_targetScale.Transitions = new Transitions { new DoubleTransition { Property = ScaleTransform.ScaleXProperty, ... } };
_targetScale.ScaleX = zoom;
```

`Transitions` 依赖 `Animatable` 的动画时钟，而 `ScaleTransform` 只是挂在 `Image.RenderTransform` 上的一个变换对象——不在可视树里，没有时钟。结果就是属性过渡不生效、数值瞬间跳到位：**静态放大看得见，推近动画看不见**。

### 修法

改成手写插值：`Stopwatch` + 16ms `DispatcherTimer`，CubicEaseOut 缓动，不依赖任何动画基础设施。

- `AnimateZoomTo(zoom, ms)`：从当前 `_targetScale.ScaleX` 缓推到 `zoom`，最后一帧精确落到目标值；
- 新增 `_zoomCts` + `StopZoomAnimation()`：设置变更（`Apply` 入口）、离开视觉树（`ReleaseBitmaps`）时立刻取消，避免动画与静态值打架；
- 推近起点从 `zoom - 0.08` 放宽到 `zoom - 0.10`，让「镜头推进」更容易被看见；
- 顺带修掉一个连带 bug：`ReleaseBitmaps()` 会把 `_disposed` 置 true，而 `OnAttachedToVisualTree` 不复位——窗口 Hide 再 Show 之后 `Apply`/`PlayIntroAsync` 第一行就 return，背景不再刷新。现在重新挂树时复位 `_disposed`。

相关文件：`Views/BackgroundLayer.axaml.cs`（新增 `using System.Diagnostics; using Avalonia.Threading;`）。

## 2. 「置顶」的对象改为 ClassIsland 顶部课表栏

### 之前的实现错在哪

- `Services/CiTopmostGuard.cs` 用 `EnumWindows` 把**本进程所有可见顶层窗口**逐个提为 topmost —— 设置页、对话框也被一起抬起来，这不是用户要的；
- 更关键的是 `ViewModels/FullScreenClockViewModel.Lifecycle.cs` 在 `Show()` / `EnsureFullScreen()` 里调 `SetMainWindowVisible(false)`，把 ClassIsland 主界面（默认就是顶部停靠的课表栏）**藏掉了**。课表栏根本没显示，自然谈不上「压在大屏上面」。

### 现在的做法

- **不再隐藏主界面**：删掉 `Show()`、`EnsureFullScreen()` 以及「已可见”分支里的三处 `SetMainWindowVisible(false)`（`Hide()` 里的 `true` 保留，用于最小化/退出时确保课表栏在）。
- **只提升主界面一个窗口**：`CiTopmostGuard.Arrange(clockHwnd, classIslandHwnd)` 依次 `SetWindowPos(HWND_TOPMOST)`——先大屏、后课表栏，Windows 的规则保证后设置者在上。不再枚举全进程窗口。
- **窗口侧持续维持**：`FullScreenClockWindow` 通过 `IClassicDesktopStyleApplicationLifetime.Windows` 找类型名含 `MainWindow` 的窗口，取其平台句柄交给守卫；`Opened`/`Activated` 各排一次，并在可见期间每 **1.5s** 重排一次（`DispatcherTimer`，窗口不可见/关闭时停止），用户点回大屏后课表栏会被重新抬回上面。

相关文件：`Services/CiTopmostGuard.cs`（重写，116 → 62 行）、`Views/FullScreenClockWindow.axaml.cs`、`ViewModels/FullScreenClockViewModel.Lifecycle.cs`。

> 注意：守卫只保证「课表栏 Z 序在大屏之上」。如果宿主里把课表栏画成了大窗口模式（而不是默认的顶部窄条），它会挡住大屏本身——这是宿主设置的结果，插件不做干预。

## 3. 「运行」页一键重置

### 行为

- 位置：「运行」页签，「最小化后暂停」下面新增一行 **重置所有设置**（图标 `E161`，描述写明范围）。
- 点「一键重置」→ FluentAvalonia `TaskDialog` 二次确认（Header「重置所有设置？」、Cancel/Reset）→ 确认后执行。
- 重置范围：**整份插件设置**——组件开关/顺序/大小位置、颜色、字号、音量阈值与记录参数、背景类型与参数、运行设置、课程目标等全部回到出厂默认；组件布局字典换成一套全新的默认实例。
- 不重置：`AdjustingLayout`（拖动中的运行时状态）、`AppliedPaletteVariant`（主题跟随状态，不是用户设置）。
- 重置后页面自动刷新：组件行重建、课程列表重载、全部转发属性重发 `PropertyChanged`、颜色与预览同步刷新；大屏侧通过 `Settings.PropertyChanged`（含 `ComponentLayouts`）收到变更并重排组件与背景。

### 实现

- `Models/PluginSettings.cs`：新增 `ResetAllToDefaults()`。用一份全新的 `PluginSettings` 当模板，反射逐项拷贝公开属性——默认值只在字段声明处维护一次，以后新增设置项无需再改重置逻辑；`ComponentLayouts` 单独处理（`defaults.EnsureComponentLayouts()` 后整体替换）。
- `Settings/SettingsPage.Run.cs`（新）：`ResetAllSettings_Click`（TaskDialog 确认 → 重置 → 刷新页面）、`NotifyAllSettingsBindings()`（反射重发本页所有属性变更）。
- `Settings/SettingsPage.Components.cs`：新增 `RefreshComponentItemsAfterReset()`（旧布局实例已换掉，重建行并重挂监听，不重复注册 `Loaded/Unloaded`）。
- `Settings/SettingsPage.axaml`：「运行」页新增重置行（`Click="ResetAllSettings_Click"`）。
