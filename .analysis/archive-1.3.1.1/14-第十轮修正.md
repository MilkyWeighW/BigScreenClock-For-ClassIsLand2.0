# 第十轮修正：位置设置冲突、全屏回退、退出闪烁、拖拽移除、说明归位、保护期基准

> 对应用户反馈（2026-11-07）：
> 1. 时钟位置和音量条位置疑似设置冲突，导致重置不生效；
> 2. 多次进入大屏时钟时有概率窗口化而非全屏；
> 3. 从大屏时钟退出时 ClassIsland 课表悬浮栏大概率闪烁；
> 4. 插件中「拖动滚动条」仍不生效，可以去掉；
> 5. 「大小」「水平位置」等通用项目的说明放到页面下方，而不是项目说明里；
> 6. 原始 Bug：上课初期保护应按课程开始时间，而不是大屏时钟打开时间。

构建验证：`pwsh -NoProfile -File .\build.ps1 -NoRestore` → **0 error / 11 warning**（与基线一致：CA1416×10 + AVLN3001×1），DLL 430,080 B，cipx 364,928 B（version 1.2.0.0 / apiVersion 2.1.0.0）。

---

## 1. 位置设置冲突 / 重置不生效

**根因**：`ApplyBodyPositions()` 每轮布局都把「被限位钳制后的实际位置」写回 `settings.ClockPositionPercent / VolumePositionPercent`，同时 `SetPositionLimits()` 又反过来收窄两个滑块的 Min/Max。于是：

- 重置把所有设置恢复默认（时钟 30%、音量条 80%），但下一帧布局立刻把实际位置写回设置、把限位再收窄；
- 两个滑块互相推挤（时钟的可用区间依赖音量条位置，音量条的又依赖时钟高度）；
- 表现出来就是「重置了但没生效」「拖这个，那个跟着跳」。

**处理**：位置本来就已经有「组件 → 位置偏移（OffsetX/OffsetY）」这一层，老的两个位置滑块是重复概念，直接下线：

- `Views/ClockSurface.axaml.cs`：`ApplyBodyPositions()` 不再回写设置，删掉 `SetPositionLimits(...)` / `WriteBack(...)` / `PercentOf(...)`；
- `Settings/SettingsPage.axaml`：删除「时钟位置」「音量条位置」两行滑块；
- `Settings/SettingsPage.Layout.cs`：删除 `ClockPositionPercent` / `VolumePositionPercent` 转发属性、`ClockPositionMin/Max`、`VolumePositionMin/Max`、`HookPositionLimits/UnhookPositionLimits`、`*PercentText`；
- `Settings/SettingsPage.axaml.cs`：删除 `HookPositionLimits()` 挂接与位置变更的通知分支。

现在位置只有一处真相：组件页每个组件的「垂直位置/水平位置」偏移；「重置所有设置」自然把偏移一并恢复默认。

顺带修了一个与重置相关的坑：`ResetAllToDefaults()` 通过反射拷贝公开属性，会把 `ComponentVisibilityMigrationVersion` 也拷回 0；下次启动时「旧显示开关 → 组件启用」的迁移会再跑一遍，把用户重置后手动关掉的组件又全部打开。现在该版本号与 `ComponentLayouts` / `AdjustingLayout` / `AppliedPaletteVariant` 一样被排除在拷贝之外。

## 2. 多次进入时有概率窗口化

**根因**：窗口是复用的（`Hide()` 而非关闭），Windows 上复用的全屏窗口在再次 `Show()` 时有概率把 `WindowState` 落回 `Normal`；原代码只在 `Show()` 之前设 `FullScreen`，`Show()` 之后没有兜底。

**处理**：

- `ViewModels/FullScreenClockViewModel.Lifecycle.cs`：`Show()` 之后再设一次 `FullScreen`，并 `Dispatcher.UIThread.Post` 再补一次（平台偶尔晚一拍应用状态）；
- `Views/FullScreenClockWindow.axaml.cs`：`Opened` 里只要当前状态不是 `FullScreen`/`Minimized` 就拉回全屏（最小化恢复交给既有的 `Activated → EnsureFullScreen`）。

## 3. 退出时课表栏闪烁

**根因**（两处叠加）：

- 退出时 `SetMainWindowVisible(true)` 对**已经显示**的 CI 主界面又调了一次 `Show()`，等于让它重走一遍显示流程 → 闪；
- 退出淡出的 480ms 里，1.5s 的置顶守卫还在跑，持续对课表栏 `SetWindowPos` → 也可能闪/跳。

**处理**：

- `SetMainWindowVisible(bool)` 改为「状态不同才动」：`visible && !win.IsVisible` 才 `Show()`，`!visible && win.IsVisible` 才 `Hide()`；
- `FullScreenClockWindow.PrepareForExit()`：退出前立刻停掉置顶守卫；`Hide()` 在开始淡出之前调用它。

## 4. 去掉组件条拖拽

本机实测组件条拖拽一直无效（Pointer 捕获与 ListBox 内部滚动/选择打架），按用户要求整体删除，保留「←前移 / →后移」箭头：

- `Settings/SettingsPage.axaml`：删掉 `ComponentBar` 的 4 个 Pointer 事件与 `.drag-source` / `.drop-target` 样式；
- `Settings/SettingsPage.Components.cs`：删掉拖拽状态字段、4 个 handler、`ResetComponentDrag/ClearDragClasses/FindComponentAt/FindDropIndexAt/FindIndexAt` 与只为拖拽引入的 using（514 → 367 行）；
- `NormalizeOrders()` 的注释同步改为「只有用户点箭头挪动时才调用」。

## 5. 通用项说明移到页面下方

- 「大小 / 水平位置 / 垂直位置」三个 `SettingsExpanderItem` 去掉 `Description`；「顺序」的说明简化为「同区先后」；
- 组件页底部固定提示栏（在 ScrollViewer 之外）改成三行说明：大小倍率含义、位置偏移的百分比含义、组件关闭与箭头排序。

## 6. 上课初期保护按课程开始时间

**根因**：`_classStartTime` 只在 CI 的时段事件 `OnTimeStateChanged` 里赋值；大屏在课中打开时不会触发那个事件，字段还是 `default` 或上一节课的旧值，`IsInProtection()` 于是用「现在 − 打开时刻」算，保护期从头开始。

**处理**：

- `ViewModels/FullScreenClockViewModel.Course.cs`：新增 `LookupCurrentClassStart()` —— 用 `NowVirtual` 遍历今日课表，找当前正在上的 `IsClass` 槽，返回 `now.Date + slot.Start`；
- `ViewModels/FullScreenClockViewModel.Noise.cs`：`IsInProtection()` 与「剩余保护时间」提示都改用 `LookupCurrentClassStart() ?? CI 事件给过的 _classStartTime`；都查不到则不保护（不再拿 `default` 算出「永远在保护」）；
- `ViewModels/FullScreenClockViewModel.Lifecycle.cs`：Show 首次打开与最小化恢复时刷新 `_classStartTime`，首帧提示即正确。

## 已知限制 / 待真机确认

- 本机没有 ClassIsland 宿主，以上涉及窗口 Z 序、全屏状态、退出淡出的行为需要真机验收；
- 「上课初期保护」在课表读不到（例如课表文件损坏/跨天缓存未重建）时会退回 CI 事件值，若两者都没有则不保护——这是刻意选择，避免误开保护导致整节课不记录；
- 位置滑块下线后，老配置里 `ClockPositionPercent/VolumePositionPercent` 的值仍保留在 Settings.json 里但不再可调；位置一律由组件偏移决定。
