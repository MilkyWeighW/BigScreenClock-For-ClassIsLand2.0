## 清单 1：设置页预览按最终输出分辨率的 40% 渲染，与最终输出解耦

- **实现位置**
  - 倍率常量：`Models/PluginSettings.cs:439-442`（`PreviewRenderScale = 0.4`，标了 `[JsonIgnore]`）。
  - 尺寸与缩放：`Settings/SettingsPage.axaml.cs:151-171`——`PreviewSourceWidth/Height` 是屏幕**逻辑**尺寸，
    `PreviewWidth/Height = 逻辑尺寸 × 0.4`，`PreviewScaleTransform = ScaleTransform(0.4, 0.4)`。
  - 取哪块屏：`SettingsPage.axaml.cs:177-203`（优先 `ScreenFromWindow`，取不到回 1920×1080）。
  - XAML：`Settings/SettingsPage.axaml:946-955`——`Panel(Width/Height=PreviewWidth/Height)` →
    `LayoutTransformControl`（0.4）→ `ClockSurface IsPreview=True` → 外层 `Viewbox`。
  - 预览面本身的设计基准：`Views/ClockSurface.axaml.cs:40-64`（`SurfaceDesignWidth/Height`，默认 1920×1080）。
- **行为**：预览不是另画小样，而是**同一份 ClockSurface** 按整屏逻辑尺寸排版、布局阶段整体缩 0.4，
  再塞进 Viewbox；因此字号、换行、边距、组件位置与大屏是同一把尺子（`SettingsPage.axaml:930-944` 注释）。
- **默认值 / 迁移**：无迁移；`PreviewRenderScale` 是常量，预览与大屏共用同一个数（`PluginSettings.cs:440-442`）。
- **回退路径**：取不到屏幕时按 1920×1080 兜底（`SettingsPage.axaml.cs:193-197`）。
- **解耦保证**：预览的缩放只在预览侧，不写回设置、不改大屏窗口尺寸（契约 `1.4-实现契约.md:58` 的要求，
  实现上没有任何从 `PreviewWidth` 写回设置的代码路径）。预览刷新走 200ms 防抖 + `RefreshForPreview`
  （`SettingsPage.axaml.cs:205-236`；`FullScreenClockViewModel.cs:616-642`），页面 Unloaded 后停表（`SettingsPage.axaml.cs:116-121`）。
- **验收点**：预览比例正确、最终输出与 1.3.1.1 一致 → 见 03 第 1 项。

## 清单 2：设置读写加 10ms 延迟、异步、不阻塞 UI

- **实现位置**：`Services/SettingsStore.cs` 全文。`CoalesceDelayMs = 10`（`:22-23`）；
  `LoadAsync` 先 `Task.Delay(10)` 再线程池读（`:38-51`）；`SaveAsync` 用 `SemaphoreSlim` + 版本号合并，
  循环里每轮先等 10ms，写完发现版本变了再写一轮（`:58-110`）；失败只 `Debug.WriteLine`，绝不抛（`:89-97`）。
- **保留同步入口**：`Plugin.SaveSettings()` 签名不变、内部 fire-and-forget 转异步（`Plugin.cs:28-39`）；
  另有 `SaveNow` 供「必须立刻可见」的时刻用（`SettingsStore.cs:125-141`）。
- **启动那一次仍同步**：`Plugin.Initialize` 必须同步拿到 Settings，注释写清了原因（`Plugin.cs:60-63`、
  `SettingsStore.cs:14-16`）。
- **叠加防抖**：设置对象变更 → 400ms 防抖 → `SaveSettings()`（`Plugin.cs:22-23, 93-102`），
  与 10ms 合并是两层，前者省「连续变更的开始次数」，后者省「落盘次数」。
- **为什么不能直接丢弃并发写**：排队而不是放弃，否则「最后一次变更」可能漏写（`SettingsStore.cs:67-69`）。
- **验收点**：UI 不卡、配置最终一致 → 见 03 第 2 项。

## 清单 3：修复壁纸背景内存溢出（生命周期、避免重复加载、限制中间纹理尺寸）

- **位图尺寸有硬上限**
  - 解码前先读图片头拿原尺寸，**绝不放大**：`Models/ImageHeader.cs:6-16`（纯字节解析，PNG/JPEG/BMP/GIF/WebP）；
    `Services/WallpaperService.cs:114-142` 据此选择解码宽度。
  - 模糊工作宽度封顶 1600、像素预算 1.25×：`Services/WallpaperCacheService.cs:43-51, 300-312`。
  - 开屏截图按 `maxWidth` 缩小抓取，避免 4K 原图 30MB+：`Services/ScreenCaptureService.cs:42-62`；
    上限 2560：`Views/BackgroundLayer.axaml.cs:40-41`。
- **缓存有上限，且长时运行会回收**
  - 内存缓存：条数 2 + 总字节 96MB 双上限，逐出最旧（`WallpaperCacheService.cs:34-41, 348-379`）。
  - 弱引用层：窗口隐藏/关闭时把强引用降级为弱引用（`:61-66, 267-298`）。
  - 磁盘缓存：启动清理只留最近 6 张（`Plugin.cs:86` → `WallpaperCacheService.cs:156-190`），
    文件名是 key 的 SHA256，key 含 mtime（`:192-211`），换壁纸自然失效。
  - 所有权约定：**返回的 Bitmap 归调用方释放**，缓存自留主副本、命中时克隆（`:23-26, 381-412`）。
- **释放点**
  - 换图/切档：`ReplaceTarget` 不立刻 Dispose（旧图还在 PriorImage 显示），延后一帧释放
    （`BackgroundLayer.axaml.cs:545-597`）。
  - 离开视觉树：`ReleaseBitmaps` 释放整屏位图并 `TrimMemoryCache`（`:675-692`）。
  - 大屏隐藏（不关闭）：窗口侧调 `ReleaseBackgroundBitmaps`（`Views/FullScreenClockWindow.Background.cs:137-147`）。
  - 截图路径所有 GDI 句柄按「先还原、再删位图、删 DC、ReleaseDC」顺序在 finally 释放
    （`ScreenCaptureService.cs:118-129`），失败返回 null 不抛（`:113-117`）。
- **中间图**：解码出的壁纸在模糊完立刻 `Dispose`（`WallpaperCacheService.cs:122-130`）；
  贴纸位图按路径缓存、同图只解一份、无用后延后一帧释放（`ClockSurface.axaml.cs:404-405, 567-598`）。
- **验收点**：反复切壁纸 / 开关大屏后内存回落 → 见 03 第 3 项。

## 清单 5：背景叠加原生实时模糊（D2D/DWM）

- **实现**：`Services/NativeBlur.cs` 用未公开的 `SetWindowCompositionAttribute` + `WCA_ACCENT_POLICY`
  （`:19-25, 51-53`），先试 acrylic 再试 blur-behind（`:62-82`）。
- **接线**：只有 `BackgroundKind.NativeBlur` 一档打开、其它档显式关闭（否则整窗一直糊着桌面）
  （`Views/FullScreenClockWindow.Background.cs:95-107`，着色 `0x99000000`）；关闭/退出时也关（`:133-143`）。
- **背景层配合**：NativeBlur/WebPage 时背景层自己什么都不画，并把在途壁纸解码作废
  （`BackgroundLayer.axaml.cs:113, 517-531`）。
- **诚实边界**：这里做的是「让 DWM 把**窗口背后**的画面实时模糊」，大屏窗口内容保持透明、
  组件直接叠上去；**不是**在 Avalonia 里再自绘一层模糊（Avalonia 没有 BackdropFilter，
  逐帧截屏+模糊在 4K 上开销不可接受，理由写在 `Views/TextMaterialLayer.cs:15-19`）。
- **回退路径**：`TryEnable` 任何一步失败都返回 false，调用方当作「没有原生模糊」，
  最坏结果是这一档退化成透明+纯色兜底，不会崩（`NativeBlur.cs:13-15, 77-81`）。
- **验收点**：背景可叠加且能实时模糊 → 见 03 第 5 项（本机无 CI 宿主，未真机验证）。

## 独立审查修复（2026-11-15 收尾批次，9 项）

这一批是 1.4.0.0 定稿后由**独立审查**发现、再修掉的缺陷。行号均已在修复后的源码上核对。

### 审查-1（P0）背景第二次打开永久失效

- **原因**：集成阶段在窗口 `Hide` 时调用了 `BackgroundLayer.ReleaseBitmaps()`，而它当时顺手把对象标记成
  `_disposed = true`；窗口 `Hide` 并不脱离可视树，`OnAttachedToVisualTree` 不会再触发，于是下次显示时
  `Apply` / `PlayIntroAsync` 在第一行就 `return`，背景永久黑掉。
- **修法**：`ReleaseBitmaps` 只释放位图、不置标记（`Views/BackgroundLayer.axaml.cs:683-698`）；
  `_disposed = true` 只在真正 `OnDetachedFromVisualTree` 时设置，并把这段踩坑写进注释
  （`Views/BackgroundLayer.axaml.cs:668-677`）；窗口隐藏路径仍只调释放
  （`Views/FullScreenClockWindow.Background.cs:137-147`）。

### 审查-2 贴纸迁移后旧单图会「复活」

- **原因**：迁移把 `CustomImageFile` 包装成第一个贴纸实例，但原字段没清；用户把贴纸全删光后，
  渲染回退逻辑发现字段还有值，又把那张旧图当成 `image` 组件画出来。
- **修法**：迁移完成时清空旧字段——`CustomImageFile = ""`、`CustomImageStretch = 0`
  （`Models/PluginSettings.cs:348-370`，清空在 `:365-366`），只跑一次（`StickerMigrationVersion`）。

### 审查-3 `WebBackgroundService.Attach` 不幂等（反复重建 Edge 窗口）

- **原因**：窗口侧 `SyncBackgroundMode` 每次可见性/状态/设置变化都会 `Attach`（
  `Views/FullScreenClockWindow.Background.cs:112-117`），而旧 `Attach` 先 `Detach` → 销毁网页窗口与
  WebView2 控制器，再重建：每切一次窗口状态就重启一次 Edge 进程。
- **修法**：同一窗口重复 `Attach` 直接返回（`Services/WebBackgroundService.cs:46-56`，`ReferenceEquals` 判等）。

### 审查-4 设置保存的两个丢数据窗口

- **集合被改**：序列化跑在线程池上而设置对象可变，UI 线程正好增删集合时抛 `Collection was modified`。
  现在写盘失败自动重试 2 次（每次隔 10ms），仍失败才记日志放弃（`Services/SettingsStore.cs:89-109`）。
- **退出时最后 400ms 的改动**：异步保存可能还没轮到，进程就没了。现在注册 `AppDomain.ProcessExit`
  同步刷一次盘：`Plugin.cs:41-53`（`FlushSettingsNow`）+ `Plugin.cs:101-103`（订阅）。

### 反馈-4 网页背景支持本地 HTML 文件

- **设置项**：`PluginSettings.BackgroundWebFile`（绝对路径，空 = 不用；有值时**优先于**网页地址；
  `Models/PluginSettings.cs:413-424`）。为什么存路径而不是复制进配置目录：网页通常要带同目录的
  css/js/图片，只搬 html 会变成空白页（`:416-419`）。
- **解析**：`WebBackgroundService.ResolveNavigationUrl`——本地文件存在才 `new Uri(fullPath).AbsoluteUri`
  转成 `file:///C:/...`（空格/中文正确转义），否则退回 `WebViewHost.NormalizeUrl(BackgroundWebUrl)`
  （`Services/WebBackgroundService.cs:376-406`）；`NavigateIfNeeded` 按最终 URL 去重（`:408-426`）。
- **接线**：`WebBackgroundService.Active` 暴露当前实例（`:40-44`），服务**自己订阅**设置变化
  （`BackgroundKind/BackgroundWebUrl/BackgroundWebFile/BackgroundColor`，`:140-170`），
  面板不用自己找窗口；窗口销毁时清空去重记录（`:274-299`）。
- **UI**：`Settings/BackgroundExtrasPanel.axaml:30-44` 新增「本地网页」区（选择 HTML / 清除 / 摘要 / 提示）；
  交互在 `Settings/BackgroundExtrasPanel.axaml.cs:160-255`——只存绝对路径、不复制文件，
  选不到本地路径或文件已不存在都有中文提示（`:189-200`），清除后退回网页地址（`:211-226`）；
  改完立刻 `Plugin.SaveSettings()` + `WebBackgroundService.Active?.Sync(...)`（`:228-255`）。
- **允许的协议**：`WebViewHost.NormalizeUrl` 放行 http/https/file/about（`Views/WebViewHost.cs:216-246`）。
