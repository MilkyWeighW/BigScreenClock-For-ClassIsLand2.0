# 真机验收清单（v1.4.0.0）

> **前提说明（必须写在最前面）**：本文档的编写环境**没有安装 ClassIsland 宿主**，
> 也无法在真实教室大屏 / 触屏 / 多屏 / 集显环境下运行插件。因此：
> 1. 本清单里的「预期」全部来自**读代码**，不是观察结果；
> 2. 构建只验证到「Release 编译 0 error / 0 warning + cipx 产出」，未验证加载与运行；
> 3. 涉及 WebView2、DWM 模糊、贴纸缩放、长时内存的项目，**必须由用户在真机逐项确认**；
> 4. 编号 1–13 与用户需求清单一一对应（第 14 条是验收点集合），详细实现位置见
>    [01-1.4.0.0-改动清单.md](01-1.4.0.0-改动清单.md)。

## 1. 构建与安装（先跑通这一步）

**步骤**

1. 在仓库根目录执行 `pwsh -File ./build.ps1`（默认出对外发布版；`-Dev` 出五位开发版）。
2. 检查产物：
   - `bin/Release/net8.0-windows/LargeScreenClockRevived.dll` 存在（约 538 KB）
   - `bin/Release/net8.0-windows/manifest.yml` 的 `version` 为 `1.4.0.0`
   - `cipx/LargeScreenClockRevived.cipx` 存在（约 844 KB）
3. 把 cipx 装进 ClassIsland，重启 CI。
4. 打开 CI 日志，确认插件加载无异常；设置页出现「大屏时钟」页签。

**预期**

- 编译 0 error / 0 warning（本次定稿构建已满足）。
- 插件版本显示 1.4.0.0；内部开发版会是 `1.4.0.0.N`（`LargeScreenClockRevived.csproj:82-141`）。
- 首次启动不弹异常、不黑屏；老用户的设置与外观「看起来没变」（迁移链见 00 §4.1）。

**失败先看**：`Plugin.Initialize`（`Plugin.cs:55-121`）是否抛异常；配置目录是否可写。

## 2. 清单 1 · 设置页预览按 40% 渲染，最终输出正常

1. 打开设置页「大屏时钟」，右栏应出现预览（"实时预览" 区块）。
2. 记下预览框的宽高比，应与大屏那块屏一致；在 1920×1080 屏上预览框应约 768×432。
3. 改时钟字号 180 → 240，预览里的时钟应**立即**变大（200ms 内），且换行/位置与大屏同比例。
4. 进入全屏时钟，确认最终输出**没有变模糊、没有变小**（预览的 0.4 只作用于预览侧）。
5. 换一台分辨率不同的机器（或用 125%/150% 缩放），预览应按新屏幕逻辑尺寸重算。

**预期**：预览是「同一份 ClockSurface 缩小」，不是另画的小样；改设置即时可见；大屏输出质量不变。
（`SettingsPage.axaml.cs:151-203`、`SettingsPage.axaml:946-955`、`ClockSurface.axaml.cs:40-64`）

**失败先看**：预览尺寸绑定 `PreviewWidth/PreviewHeight` 是否随 `UpdatePreviewSize` 通知；
`LayoutTransformControl` 是否包住了预览面。

## 3. 清单 2 · 设置异步 10ms、UI 不卡

1. 在大屏时钟**正在运行**时打开设置页，快速拖动任一滑块（如音量阈值、动画速率）十几秒。
2. 观察设置页与背后大屏是否掉帧、输入是否跟手。
3. 拖完立刻看 `Settings.json` 的修改时间：应**只写一次或很少几次**（400ms 防抖 + 10ms 合并）。
4. 强制结束 CI（模拟崩溃）后重启，确认最后几次设置基本落盘（最多丢最后 10~400ms 内的改动）。

**预期**：无「拖一下就卡半秒」；磁盘写入明显少于改动次数；异常不冒泡到 UI。
（`Services/SettingsStore.cs:22-119`、`Plugin.cs:22-23, 77-85`）

**失败先看**：是否有同步 `SaveConfig` 调用绕过 `SettingsStore`（本版启动加载仍同步，属预期）。

## 4. 清单 3 · 壁纸内存长时稳定

1. 设置背景为「提取当前壁纸」，景深放大 1.15、模糊 24。
2. 开大屏 → 关闭 → 再开，重复 **30 次**；每次间隔约 3 秒。
3. 每 10 次记录一次任务管理器里 CI 进程的私有工作集。
4. 换一张 4K 壁纸再重复 10 次。
5. 保持大屏打开 **2 小时以上**（模拟一节课 + 课间），观察是否有持续上涨。

**预期**：内存有涨落但**不单调上涨**；第 30 次与第 10 次处于同一量级；无崩溃、无 GDI 句柄耗尽。
隐藏大屏后内存应明显回落（弱引用降级 + 位图释放）。
（`WallpaperCacheService.cs:34-51, 267-298, 348-379`；`BackgroundLayer.axaml.cs:675-692`；
`FullScreenClockWindow.Background.cs:116-131`）

**失败先看**：`cache/` 目录是否越积越多（应 ≤ 6 张）；是否每次开屏都重新解码（可看日志/耗时）。

## 5. 清单 4 · 背景/组件分开渲染；WebView2 可用与不可用两条路径

### 5A 可用路径（本机已装 WebView2 运行时）

1. 背景选「网页」，填入一个可访问地址（如内网首页或 `https://example.com`）。
2. 进大屏：网页应铺满整屏作为**背景**，时钟/组件浮在网页之上，清晰可读。
3. 拖动设置页窗口 / 改分辨率 → 网页应跟随铺满（250ms 内），不出现只盖左上角。
4. 在 **150% 缩放**的 4K 屏上重复第 2 步：网页内容应与屏幕同比例（不应出现「网页按 100% 画、字明显偏小」）。
5. 最小化大屏（不关）再点回 → 网页**不应重新加载/闪白**（URL 未变不重导航）；
   隐藏超过 12 秒再恢复 → 这时才重建并重新加载（属预期）。
6. 切到别的背景档 → 网页窗口应收掉、背景正常。

**本地 HTML（验收反馈新增）**：

7. 在「本地网页」区点「选择 HTML」，选一个带同目录 `css/js/图片` 的本地页面 → 大屏应显示该页面，
   且这些相对资源都要能加载出来（不是空白页）。
8. 清除本地网页 → 应回退到上面的网页地址；地址也为空时保持纯色兜底。
9. 选中 html 后把它挪走/删掉 → 再进大屏应保持纯色（不崩、不弹框），设置页切回时给「文件不存在」类提示。

**预期**：网页在**下层**、组件在上层；无右键菜单/DevTools/状态栏；不抢焦点；本地 html 优先于网址。
（`WebBackgroundService.cs:172-197, 376-426`；`WebBackgroundWindow.axaml.cs:94-105`；`WebViewHost.cs:70-88`；
`BackgroundExtrasPanel.axaml.cs:160-255`）

### 5B 不可用路径（卸载/禁用 WebView2 运行时，或找一台没装的机器）

1. 背景设置里把「网页」这一档点下去。
2. 应**当场被拦下**：档位不生效，并显示中文原因（未检测到运行时 / 缺 Loader 等）。
3. 其余四个背景档（壁纸/纯色/自定义图/实时模糊）应照常可用。
4. 即使通过 Settings.json 手工把 `BackgroundKind` 改成 4，进大屏也只应看到兜底纯色，不黑屏不崩。

**预期**：静默降级 + 明确提示；大屏功能不受影响。
（`SettingsPage.Background.cs:21-48`；`WebView2Availability.cs:62-102`；`WebBackgroundService.cs:119-127`）

**失败先看**：`webview2/` 子目录是否可写；CI 日志里 WebView2 初始化异常；`UnavailableReason` 文案。

## 6. 清单 5 · 背景可叠加并原生实时模糊

1. 背景选「实时模糊」。
2. 桌面上打开一个内容丰富的窗口（浏览器/图片）放到最大，然后进大屏。
3. 应看到**桌面画面被实时模糊**作为背景，组件清晰叠在上面；
   移动背后的窗口内容时，模糊层应跟着变（不是一张静态截图）。
4. 有开屏动画时，应先看到压暗的桌面截图，再淡入模糊层。
5. 切回「壁纸」档：模糊必须**立刻关掉**（否则整窗会一直糊着）。
6. 在 Win10 老版本 / 远程桌面 / 关闭透明效果的环境试一次：应退化为透明+纯色兜底，不崩。

**预期**：模糊来自 DWM（窗口背后），不是自绘；切档能正确开关。
（`NativeBlur.cs:62-82`；`FullScreenClockWindow.Background.cs:74-93`；`BackgroundLayer.axaml.cs:517-529`）

**注意**：这一项**必须真机看**，代码无法证明 DWM 在你的系统版本上是否接受 acrylic。

## 7. 清单 6 · 动画无明显卡顿

1. 连续进出大屏 10 次（设置页按钮 / 托盘菜单 / 课程自动触发各几次）。
2. 每次观察：压暗截图 → 背景交叉淡入 → 组件淡入，三拍是否连贯，有无「先闪一下完整界面」。
3. 把「动画速率」调到 0.5 与 2.0 各试几次。
4. 在壁纸档下快速拖「景深放大」「模糊半径」滑块：画面应跟手，不应每次都长时间卡住。
5. 退出时观察整窗淡出（约 480/speed ms），不出现背景「啪」地消失。

**预期**：第二次及以后开屏也不闪；拖滑块不重复解码整张壁纸（只有路径/宽度/半径变化才重解）。
（`BackgroundLayer.axaml.cs:173-234, 236-319, 374-390`；`ClockSurface.axaml.cs:263-338`；
`FullScreenClockWindow.axaml.cs:207-244`）

## 8. 清单 7 · 主题色与 CI 一致、可回退

1. 在 CI 设置里换一个**明显的**强调色（如橙红）。
2. 打开大屏时钟 → 进度条「已进行」部分应变成该强调色（前提：你没手动改过进度条色）。
3. 打开设置页「外观 → 主题色」：应显示当前强调色 HEX，跟随开关为开。
4. 在插件设置里手动把进度条色改成绿色 → 强调色**不应**再覆盖它（用户优先）。
5. 关掉「跟随 ClassIsland 主题色」→ 配色应立刻回到插件主题自带那套。
6. 在 CI 里换主题（明↔暗）→ 大屏与预览应即时跟着换。

**预期**：单向读取、只影响进度条（未手动改过时）；关闭/读不到 → 回退主题自带色。
（`CiThemeReader.cs:25-32`；`ClockThemeApplier.cs:99-137`；`FullScreenClockViewModel.cs:485-544`；
`SettingsPage.axaml:722-741`）

**注意**：强调色资源键是按 FluentAvalonia 命名**猜的**（5 个候选），若 CI 版本换了资源键，
表现是「读不到 → 静默回退」，不会报错——见 04 §3。

## 9. 清单 8 · 组件长宽比 / 字体可配并持久化

1. 组件页选中「时钟」，把长宽比 X 拖到 1.5：时钟应只变宽、不变高，位置不跑。
2. 字体族选一个系统中文字体、字号 200、字重 700：时钟数字应三处同时变化。
3. 选中「课程信息」改字体：只影响该组件，不影响时钟。
4. 全部改回默认（字体空、字号 0、字重 0、拉伸 1）：外观应与改之前**逐像素一致**。
5. 关闭 CI 再打开：上述设置应保持（存 `Settings.json` 的 `ComponentLayouts`）。
6. 在设置页「一键重置」后：组件外观恢复默认，但组件显隐/顺序不被重置逻辑误改。

**预期**：默认值下零影响；改动即时生效；重启保持；重置行为符合 `ResetAllToDefaults` 的例外清单。
（`ComponentLayout.cs:66-209`；`ComponentHost.cs:160-308`；`PluginSettings.cs:913-960`）

## 10. 清单 9 · overlay 只改文字材质

> **验收反馈后语义已变**：材质作用在**字形填充**上（半透明渐变 + 小半径模糊/投影），
> 不是文字背后垫外框。

1. 组件页选中「时钟」，文字材质选「磨砂」：**文字本身**应变成半透明、上下略有浓淡的「磨砂字」，
   **不应**出现文字背后的一块圆角薄片/玻璃块。
2. 切「液态玻璃」：字应更亮、更「厚」——顶部偏白高光 + 字下一点半透明投影。
3. 切回「无」：文字应**完全恢复**原来的颜色与清晰度（不能残留半透明或模糊）。
4. 换主题（明↔暗）或在设置里改该组件的文字颜色：材质应按新颜色重建，不能停留在旧色的渐变上。
5. 缩放/移动该组件：文字与效果一起走，不残留、不抖动。
6. 在**没有** DWM 透明效果的环境（远程桌面/软件渲染）重复 1–3：应只是「半透明渐变的字」，不崩、不糊成一片。
7. 观察 CPU/GPU：无材质时不应有额外开销；有材质时不应每帧重建画刷。

**预期**：材质只改文字本身；无材质零开销；两种档位观感可区分；切回/换主题能干净还原。
（`Views/TextMaterialLayer.cs:20-28, 54-65, 123-183, 186-221, 226-241`；`Views/ComponentHost.cs:346-365`）

**诚实提示**：这是**字形填充层面的近似**（渐变 + 小半径模糊/投影），不是逐像素折射；
DWM 只在实时模糊档作为底层背景，材质本身不吃背景像素（`TextMaterialLayer.cs:13-18`）。

## 11. 清单 10 · 天气 / 日期 / 倒计时默认隐藏且可恢复

> 验收反馈后默认隐藏从 3 项扩到 **6 项**，并对老配置补一次迁移。

1. **新装用户**（或删掉 `Settings.json` 后）进大屏：日期、天气、顶部倒计时、**顶部降雨、顶部文本提醒、
   左上角提醒面板**这六项都**不应出现**。
2. 打开设置页组件页：这六项应在「＋ 添加组件」列表里（未启用）。
3. 逐个加回：大屏应正常显示，与 CI 主界面/课表栏重合也照常显示。
4. **老用户**（1.4.0.0 之前升上来、原本开着其中几项）：本次升级后这六项应被**统一关掉一次**
   （迁移 `ComponentDefaultsMigrationVersion`，只跑一次）；之后手动打开不会被再关。
5. 再次关闭 → 大屏立即隐藏且**不留空档**（不占位）。
6. 「运行 → 重置所有设置」后：显隐回到默认（六项隐藏），迁移不会因为重置而重跑。

**预期**：新装与升级都默认隐藏这六项；用户手动开关后不再被迁移覆盖。
（`ComponentLayout.cs:245-263`；`PluginSettings.cs:1013-1047`；`Plugin.cs:73-76`；`SettingsPage.axaml:58-92`）

## 12. 清单 11 · 时间随 CI 偏移、失败回退

1. 在 CI 设置里把时间偏移设为 **+300 秒**（打铃提前 5 分钟）。
2. 进大屏：时钟读数应比系统时间**快 5 分钟**；课程信息/打铃时间/进度条应与读数一致（同一条时间轴）。
3. 把偏移改回 0：读数应与系统时间一致。
4. 观察秒跳变：应稳定 1 秒一跳，不出现「卡两秒再跳两下」。

**预期**：读数与课程/打铃对齐；偏移 0 时与 1.3.1.1 完全一致。
（`CiTimeService.cs:61-102`；`FullScreenClockViewModel.cs:186-193`；`Lifecycle.cs:333-349`）

**回退验证**（较难构造）：若 CI 时间服务不可用，应静默退回系统时间且不刷日志——
可在日志里确认最多一条 `[CiTimeService] 读取 CI 时间失败`。

## 13. 清单 12 · 贴纸多实例一一对应、不随机切换

> 验收反馈后「自定义图片」静态组件已删除，**贴纸是图片的唯一入口**。

1. 组件页：确认**没有**独立的「自定义图片 / 图片填充方式」行；选任意组件时下图里也不应出现「图片」区块。
   图片入口只在贴纸面板（组件页签内）。
2. 组件页 → 贴纸面板，添加 3 张不同的图（如 1.png=1、2.png=2、3.png=3，图上写数字）。
2. 进大屏：应看到三张贴纸，**每张显示自己那张图**，位置可各不相同（各自有布局键）。
3. 分别调第 2 张的大小/位置/不透明度：只有第 2 张变，其它两张不动。
4. 删除第 2 张：它应立即消失且不留空壳；第 1、3 张不受影响。
5. 同一张图被两个实例引用：两张都应显示（内部只解码一份，行为上看不出来）。
6. 把其中一张换成别的图：应立即换过来，不出现「还显示旧图」。
7. 重启 CI：三张图与各自布局应完整恢复。
8. 老用户（1.3.1.1 只有一张自定义图）升级：那一张应自动变成「贴纸 1」，外观不变。

**预期**：一实例一图、一一对应；无随机切换；重启保持；老图不丢。
（`ImageInstance.cs:22-44`；`ClockSurface.axaml.cs:382-633`；`PluginSettings.cs:332-386`；
