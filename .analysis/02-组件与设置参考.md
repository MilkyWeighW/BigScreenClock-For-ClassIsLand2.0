## 2. `ComponentLayout` 全字段语义

类定义：`Models/ComponentLayout.cs:21-219`。全部字段都只做「在自然布局上叠加一点微调」，
默认值下与「没有这套组件设置」逐像素一致（`:7-20`）。

| 字段 | 类型 | 范围 | 默认 | 语义 / 为什么 | 行号 |
|---|---|---|---|---|---|
| `Enabled` | bool | — | true | 显不显示；关掉不渲染也不占位。不影响大小/位置值 | `:148-157` |
| `Scale` | double | 0.1–2.0 | 1.0 | 整体缩放，走 RenderTransform 不参与布局 | `:121-129` |
| `StretchX` | double | 0.1–3.0 | 1.0 | 横向拉伸（长宽比的一半），与 Scale 相乘 | `:66-74` |
| `StretchY` | double | 0.1–3.0 | 1.0 | 纵向拉伸 | `:76-81` |
| `OffsetX` | double | -100–100 | 0 | 水平偏移，单位 = 大屏宽度的百分比 | `:131-139` |
| `OffsetY` | double | -100–100 | 0 | 垂直偏移，单位 = 大屏高度的百分比 | `:141-146` |
| `Opacity` | double | 0–1 | 1 | 整块不透明度；0 = 看不见但仍占布局位置 | `:169-177` |
| `Order` | int? | — | null | 同一分区内先后；null = 按清单顺序 | `:159-167` |
| `FontFamily` | string | — | empty | 组件内文字字体族；空 = 跟随大屏默认 | `:83-91` |
| `FontSize` | double | 0–400 | 0 | 组件内文字字号（px）；0 = 用组件自己的默认字号 | `:93-100` |
| `FontWeight` | int | 100–900 / 0 | 0 | 映射到 Avalonia 具名字重（`Views/ComponentHost.cs:304-315`）；0 = 默认 | `:102-109` |
| `TextMaterial` | int | 0–2 | 0 | 0 无 / 1 磨砂 / 2 液态玻璃。**改的是文字字形填充**（渐变+效果），不是背后垫薄片 | `:111-119` |

由此派生（**不存盘**）：

- `IsDefault`（`:179-191`）：设置页用它决定「恢复默认」按钮灰不灰。
- `Reset()`（`:193-209`）：恢复外观（Scale/Offset/Opacity/Stretch/字体/材质），**不动** `Enabled` 与 `Order`。

### 生效顺序（为什么看起来没变）

`Views/ComponentHost.cs:172-186` 每次布局变化都重算：先 `ApplyTemplate()`（`:178`，保证材质有文字可改）
→ `Opacity`（`:180-181`）→ `ApplyTransform`（`:183`）→ 字体（`:184`）→ 材质（`:185`）。
`ApplyTransform`（`:193-219`）先按**组件中心**缩放/拉伸、再按屏幕百分比平移；三者都为单位值时
直接 `RenderTransform = null`（`:203-208`）。

另：一键重置会换掉整张 `ComponentLayouts` 字典，壳会自己在实例变化时重挂布局（`:157-166`）。

## 3. 贴纸实例与 id 约定

### 3.1 id 规则

- 实例 id：8 位随机十六进制（`Guid.NewGuid().ToString("N")[..8]`），只允许小写字母/数字/短横线，
  写入时清洗、非法则重新生成（`Models/ImageInstance.cs:18, 48-55`）。新建实例时会主动避开已有 id
  （`Models/PluginSettings.cs:377-389`）。
- 组件 id = `image:` + 实例 id（前缀常量 `ComponentIds.ImagePrefix`，`ImageInstance.cs:73-74`）。
- 旧版单图组件 id 保留为 `image`（`ComponentIds.LegacyImage`，`:76-77`），**只用于迁移清理**：
  `MigrateOverlappingComponentDefaults` 会把布局字典里这一项删掉（`PluginSettings.cs:1043-1044`）。
- 判定：`ComponentIds.TryGetImageInstanceId(id, out instanceId)`（`:79-87`）；
  `ComponentCatalog.Find` 对贴纸 id 返回合成的「贴纸」描述（`ComponentLayout.cs:271-274`）。

### 3.2 实例字段

| 字段 | 说明 | 行号 |
|---|---|---|
| `Id` | 稳定 id、存盘；同时是 `ComponentLayouts` 的字典键后缀 | `ImageInstance.cs:22-27` |
| `File` | 插件配置目录里的**副本**文件名；空 = 没选图、不渲染 | `:29-34` |
| `Stretch` | 0 完整显示 / 1 铺满裁切 / 2 拉伸 | `:36-41` |
| `ComponentId` | 计算属性（`[JsonIgnore]`） | `:43-44` |

### 3.3 生命周期与迁移

- 老配置只有一张 `CustomImageFile`：`EnsureImageInstances()` 把它包装成第一个实例，迁完**清空旧字段**
  （`CustomImageFile=""`、`CustomImageStretch=0`，`:363-366`），`StickerMigrationVersion` 只迁一次
  （`Models/PluginSettings.cs:348-374`）。
- **贴纸是图片的唯一入口**：静态「自定义图片」组件已删除；`ClockSurface` 的 `ResolveStickerSources`
  只遍历 `ImageInstances`，不再读旧单图字段（`Views/ClockSurface.axaml.cs:417-431`；注释 `:383-389`
  说明「两边都读会让同一张图被画两遍」）。
- 启动时补布局（`Plugin.cs:70` → `PluginSettings.cs:928-936`），设置页打开时再兜一次。
- 增删实例同时增删布局键（`:377-397`），不删磁盘文件；未被引用的副本由
  `ComponentImageStore.PruneUnusedInstanceFiles` 清理（`Models/ComponentImageStore.cs:187`）。

### 3.4 贴纸的尺寸与解码（内存）

尺寸算法（与 1.3.1.1 一致）：基准边长 = 屏幕宽 × 30%（下限 80px），按原图长宽比算高；
高度超过屏幕高 60% 时按高度反算宽度；再大靠组件 `Scale` 放大（`Views/ClockSurface.axaml.cs:602-621`）。
默认位置：主体区右侧居中、右边留 40（`SyncStickerHosts` 内，`:437-495`）。

解码：先读文件头拿原尺寸，**比屏幕逻辑宽还大才** `DecodeToWidth`，否则整图解码——
避免一张几千万像素的原图整张进内存（`Views/ClockSurface.axaml.cs:538-564`）。

## 5. 预览 40% 的坐标关系

```
真实大屏窗口（逻辑尺寸 = 屏幕物理尺寸 / Scaling）
  ClockSurface 实测尺寸 W x H
        |  <-- 同一份 XAML / 同一个 ViewModel / 同一套字号与边距
        v
  SettingsPage.UpdatePreviewSize() 取屏幕逻辑尺寸 -> PreviewSourceWidth/Height = W x H
        |
        +-- PreviewWidth  = W x 0.4
        +-- PreviewHeight = H x 0.4
        +-- LayoutTransformControl(ScaleTransform(0.4, 0.4))
                |  布局阶段就按 0.4 参与测量
                v
           Panel(Width=PreviewWidth, Height=PreviewHeight) -> Viewbox(Uniform)
```

关键点：

- `ClockSurface` 内部**仍然拿到整屏尺寸**（W×H），字号/换行/位置计算与全屏一致；
  缩放只发生在最外层（`Settings/SettingsPage.axaml.cs:165-171` 注释）。
- 屏宽取「CI 设置页所在窗口那块屏」的逻辑尺寸（`:177-203`），取不到按 1920×1080。
- 预览是**只读**的：`IsHitTestVisible=False`、`IsPreview=True`（`Settings/SettingsPage.axaml:918-925`）；
  不写设置、不起弹幕定时器（`ClockSurface.axaml.cs:22-24`、`:1081-1094`）。
- 预览补「假内容」占位（课程/计数/正在记录），只在真实内容为空时显示（`ClockSurface.axaml.cs:714-731`）。

## 6. 主题色规则

### 6.1 解析链

```
EffectiveMode(settings)                        ClockThemeApplier.cs:31-34
  |- BackgroundEnabled == true -> BackgroundThemeMode -> ToClockThemeMode()   BackgroundThemeMode.cs:24-33
  \- else                      -> ThemeMode
        v
ClockTheme.ResolveVariant(mode, ciIsDark, backgroundIsDark)   ClockTheme.cs:178-187
  |- Light  -> 明亮调色板
  |- Dark   -> 黑暗调色板
  |- Auto   -> backgroundIsDark 有值 ?（亮图->白字）: 跟随 CI
  \- Follow -> ciIsDark ? 黑暗 : 明亮
        v
ClockTheme.PaletteOf(variant) -> ClockBrushes（整批画刷，换主题只通知一次）  ClockBrushes.cs:6-10
```

（`Models/ClockTheme.cs:183-185`）——亮图配白字（先用深色玻璃把背后压暗），暗图配黑字。
原因写在 `ClockTheme.cs:15-21`。

### 6.4 强调色介入的唯一位置

**只有进度条**：`ResolveProgressColor`（`ClockThemeApplier.cs:116-137`）。
