## 2. `ComponentLayout` 全字段语义

类定义：`Models/ComponentLayout.cs:21-219`。全部字段都只做「在自然布局上叠加一点微调」，
默认值下与「没有这套组件设置」逐像素一致（`:7-20`）。

| 字段 | 类型 | 范围 | 默认 | 语义 / 为什么 | 行号 |
|---|---|---|---|---|---|
| `Enabled` | bool | — | true | 显不显示；关掉不渲染也不占位（同一分区后面的组件补上来）。不影响大小/位置值 | `:148-157` |
| `Scale` | double | 0.1–2.0 | 1.0 | 整体缩放，走 RenderTransform 不参与布局，不会把邻居挤走 | `:121-129` |
| `StretchX` | double | 0.1–3.0 | 1.0 | 横向拉伸（长宽比的一半），与 Scale 相乘 | `:66-74` |
| `StretchY` | double | 0.1–3.0 | 1.0 | 纵向拉伸 | `:76-81` |
| `OffsetX` | double | -100–100 | 0 | 水平偏移，单位 = 大屏宽度的百分比 | `:131-139` |
| `OffsetY` | double | -100–100 | 0 | 垂直偏移，单位 = 大屏高度的百分比 | `:141-146` |
| `Opacity` | double | 0–1 | 1 | 整块不透明度；0 = 看不见但仍占布局位置 | `:169-177` |
| `Order` | int? | — | null | 同一分区内先后；null = 按清单顺序；不会把组件搬到别的区 | `:159-167` |
| `FontFamily` | string | — | empty | 组件内文字字体族；空 = 跟随大屏默认 | `:83-91` |
| `FontSize` | double | 0–400 | 0 | 组件内文字字号（px）；0 = 用组件自己的默认字号 | `:93-100` |
| `FontWeight` | int | 100–900 / 0 | 0 | 映射到 Avalonia 具名字重（`Views/ComponentHost.cs:306-317`）；0 = 默认 | `:102-109` |
| `TextMaterial` | int | 0–2 | 0 | 0 无 / 1 磨砂 / 2 液态玻璃，只覆盖文字外框 | `:111-119` |

由此派生（**不存盘**）：

- `IsDefault`（`:179-191`）：设置页用它决定「恢复默认」按钮灰不灰。
- `Reset()`（`:193-209`）：恢复外观（Scale/Offset/Opacity/Stretch/字体/材质），**不动** `Enabled` 与 `Order`。

### 生效顺序（为什么看起来没变）

`Views/ComponentHost.cs:175-189` 每次布局变化都重算：先 `ApplyTemplate()`（`:179-181`，保证材质层有地方挂）
→ `Opacity`（`:183-184`）→ `ApplyTransform` → 字体 → 材质。`ApplyTransform`（`:196-215`）先按**组件中心**
缩放/拉伸，再按屏幕百分比平移；三者都为单位值时直接 `RenderTransform = null`（`:206-211`），
默认配置零变换开销。

另：一键重置会换掉整张 `ComponentLayouts` 字典，壳会自己在实例变化时重挂布局
（`Views/ComponentHost.cs:154-168`）。

## 3. 贴纸实例与 id 约定

### 3.1 id 规则

- 实例 id：8 位随机十六进制（`Guid.NewGuid().ToString("N")[..8]`），只允许小写字母/数字/短横线，
  写入时清洗、非法则重新生成（`Models/ImageInstance.cs:18, 48-55`）。
- 组件 id = `image:` + 实例 id（前缀常量 `ComponentIds.ImagePrefix`，`ImageInstance.cs:73-74`）。
- 旧版单图组件 id 保留为 `image`（`ComponentIds.LegacyImage`，`:76-77`）。
- 判定：`ComponentIds.TryGetImageInstanceId(id, out instanceId)`（`:79-87`）；
  `ComponentCatalog.Find` 对贴纸 id 返回合成的「贴纸」描述（`ComponentLayout.cs:271-273`）。

### 3.2 实例字段

| 字段 | 说明 | 行号 |
|---|---|---|
| `Id` | 稳定 id、存盘；同时是 `ComponentLayouts` 的字典键后缀 | `ImageInstance.cs:22-27` |
| `File` | 插件配置目录里的**副本**文件名；空 = 没选图、不渲染 | `:29-34` |
| `Stretch` | 0 完整显示 / 1 铺满裁切 / 2 拉伸 | `:36-41` |
| `ComponentId` | 计算属性（`[JsonIgnore]`） | `:43-44` |

### 3.3 生命周期与迁移

- 老配置只有一张 `CustomImageFile`：`EnsureImageInstances()` 把它包装成第一个实例，迁完**清空旧字段**
  （`CustomImageFile=""`、`CustomImageStretch=0`，`:365-366`），`StickerMigrationVersion` 只迁一次
  （`Models/PluginSettings.cs:348-370`）。清空是审查修复：否则用户把贴纸全删光后旧单图会复活。
- 启动时补布局（`Plugin.cs:70` → `PluginSettings.cs:915-923`），设置页打开时再兜一次。
- 增删实例同时增删布局键（`:388-398`），不删磁盘文件；未被引用的副本由
  `ComponentImageStore.PruneUnusedInstanceFiles` 清理（`Models/ComponentImageStore.cs:187`）。
- 渲染回退：实例列表为空但还有 `CustomImageFile` 时按旧单图（id=`image`）渲染
  （`Views/ClockSurface.axaml.cs:418-447`）。迁移后该字段已被清空，所以这条回退只服务「迁移没跑」的旧配置。

### 3.4 贴纸的尺寸与解码（内存）

尺寸算法（与 1.3.1.1 一致）：基准边长 = 屏幕宽 × 30%（下限 80px），按原图长宽比算高；
高度超过屏幕高 60% 时按高度反算宽度；再大靠组件 `Scale` 放大（`Views/ClockSurface.axaml.cs:614-633`）。
默认位置：主体区右侧居中、右边留 40（`SyncStickerHosts` 内，`:449-508`）。

解码（审查修复）：先读文件头拿原尺寸，**比屏幕逻辑宽还大才** `DecodeToWidth`，否则整图解码——
避免一张几千万像素的原图整张进内存（`Views/ClockSurface.axaml.cs:549-575`）。

## 5. 预览 40% 的坐标关系

```
真实大屏窗口（逻辑尺寸 = 屏幕物理尺寸 / Scaling）
  ClockSurface 实测尺寸 W x H
        |  <-- 同一份 XAML / 同一个 ViewModel / 同一套字号与边距
        v
  SettingsPage.UpdatePreviewSize() 取屏幕逻辑尺寸 -> PreviewSourceWidth/Height = W x H
        |
        +-- PreviewWidth  = W x 0.4
        +-- PreviewHeight = H x 0.4
        +-- LayoutTransformControl(ScaleTransform(0.4, 0.4))
                |  布局阶段就按 0.4 参与测量（不是 RenderTransform，不模糊不裁切）
                v
           Panel(Width=PreviewWidth, Height=PreviewHeight) -> Viewbox(Uniform)
```

关键点：

- `ClockSurface` 内部**仍然拿到整屏尺寸**（W×H），所以字号、换行、组件位置的计算与全屏完全一致；
  缩放只发生在最外层（`Settings/SettingsPage.axaml.cs:165-171` 注释）。
- 屏宽取的是「CI 设置页所在窗口的那块屏」的逻辑尺寸，多屏时跟随（`:177-203`），取不到按 1920×1080。
- 预览是**只读**的：`IsHitTestVisible=False`、`IsPreview=True`（`SettingsPage.axaml:948, 953`）；
  预览那份不写设置、不起弹幕定时器（`ClockSurface.axaml.cs:22-24`、`:1093-1096`）。
- 预览启动时补「假内容」占位（课程/计数/正在记录），只在真实内容为空时显示，不污染 VM
  （`ClockSurface.axaml.cs:726-743`）。

## 6. 主题色规则

### 6.1 解析链

```
EffectiveMode(settings)                        ClockThemeApplier.cs:31-34
  |- BackgroundEnabled == true -> BackgroundThemeMode -> ToClockThemeMode()   BackgroundThemeMode.cs:24-33
  \- else                      -> ThemeMode
        v
ClockTheme.ResolveVariant(mode, ciIsDark, backgroundIsDark)   ClockTheme.cs:178-187
  |- Light  -> 明亮调色板
  |- Dark   -> 黑暗调色板
  |- Auto   -> backgroundIsDark 有值 ?（亮图->白字）: 跟随 CI
  \- Follow -> ciIsDark ? 黑暗 : 明亮
        v
ClockTheme.PaletteOf(variant) -> ClockBrushes（整批画刷，换主题只通知一次）  ClockBrushes.cs:6-10
```

「自动」档方向**故意反直觉**：`backgroundIsDark ? VariantLight : VariantDark`
（`Models/ClockTheme.cs:183-185`）——亮图配白字（先用深色玻璃把背后压暗），暗图配黑字。
原因写在 `ClockTheme.cs:15-21`：亮壁上再盖白，字和底一起往上飘，最淡的几处最先糊掉。

### 6.4 强调色介入的唯一位置
