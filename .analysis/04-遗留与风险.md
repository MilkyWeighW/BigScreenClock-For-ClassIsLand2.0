## 2. 设计上的近似（不是缺陷，但别误解）

### 2.1 文字材质：DWM 透出 + Skia 静态近似，不是逐像素折射

`TextMaterialLayer` 的两种材质实际只有三件事：半透明薄片、描边、模糊半径固定的 `BlurEffect`
（`Views/TextMaterialLayer.cs:218-227, 274-308`）。所谓「磨砂」在**原生路径**下靠的是整窗 DWM
透明 + 窗口背后的模糊透出来（`:18-20`）；**没有** DWM 时只是 Skia 的静态柔化近似。
「液态玻璃」是「外圈描边 + 主体 + 顶部高光」三层画出来的体积感，注释也写明不做逐像素色散
（`:297-298`）。即「D2D/DWM」在实现上是**近似**：一条走 DWM 透出、一条走 Skia 静态层叠，
都不是「对文字背后像素做真实模糊/折射」。

### 2.2 背景「实时模糊」是 DWM 模糊窗口背后，不是自绘一层模糊

`BackgroundKind.NativeBlur` 下背景层**什么都不画**（`BackgroundLayer.axaml.cs:517-531`），
模糊来自未公开 API `SetWindowCompositionAttribute`（`NativeBlur.cs:62-82`）。所以：
模糊内容是「窗口背后的桌面/其它窗口」；大屏窗口必须保持透明；不支持「只在某一块区域模糊」。

### 2.3 主题「自动」档的方向是反的，这是故意的

`backgroundIsDark ? 明亮 : 黑暗`（`Models/ClockTheme.cs:183-185`）——亮图配白字；
理由见 `ClockTheme.cs:15-21`。读代码时别以为是写反了。

### 2.4 强调色只在「用户没改过进度条色」时接管

判据是「当前值等于该调色板默认值」（`ClockThemeApplier.cs:124-137`）。用户改过进度条色后，
即使打开「跟随 ClassIsland」也不会变强调色——这是设计意图（用户优先），不是 bug。

### 2.5 高 DPI 下的单位混用是刻意的

- `CoreWebView2Controller.Bounds` 要物理像素、`ClientSize` 是 DIP，所以显式乘 `RenderScaling`
  并设 `RasterizationScale`（`WebViewHost.cs:120-142`、`WebBackgroundWindow.axaml.cs:94-105`）；
- 壁纸解码宽度用屏幕**物理**宽（`BackgroundLayer.axaml.cs:624-633`），预览用**逻辑**宽
  （`SettingsPage.axaml.cs:177-203`）。两处单位不同是有意的。

## 4. 仍未修的风险（按对用户的影响排序）

### R-1（中高）多屏 / 非主屏下，开屏截图与壁纸解码仍取主屏

- 截图用 `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 并 `BitBlt` 屏幕 DC `(0,0)`
  （`Services/ScreenCaptureService.cs:49-104`），拿到的是**主屏**尺寸与主屏画面。
- 壁纸解码宽度取 `Screens.Primary`（`Views/BackgroundLayer.axaml.cs:624-633`，兜底 1920 `:630`）。
- 而设置页预览用「窗口所在那块屏」（`SettingsPage.axaml.cs:177-203`）。

**后果**：大屏开在副屏（分辨率/缩放与主屏不同）时，开屏过渡垫底的是主屏桌面截图，
壁纸按主屏宽解码导致模糊半径换算偏差、清晰度不匹配。不影响功能正确性，只影响观感与内存预算。
修法（未实施）：截图与壁纸解码都改用 `MonitorFromWindow(大屏 hwnd)` 的显示器矩形/尺寸。

### R-2（中）强调色资源键仍是「按 FluentAvalonia 猜的」

`CiThemeReader` 的 5 个候选键（`Helpers/CiThemeReader.cs:25-32`）没有 CI 官方 API 背书
（`:10-15` 也写明「插件 SDK 没有公开的强调色接口」）。CI 换主题资源命名后，表现是
**静默读不到 → 回退主题自带色**（不崩、不报错，但用户会觉得「跟随没效果」）。

### R-3（中低）组件字体恢复用的是「首次快照」

`ComponentHost` 在第一次看到某个 `TextBlock` 时记一份字体快照（`Views/ComponentHost.cs:271-279`），
把组件字体改回默认/组件离开可视树时无条件写回这份快照（`:320-339`）。
**极端路径**：如果快照之后该文字块自己的绑定值又变了（例如 CI 主界面字体被改、`ClockFontFamily` 重新求值），
「恢复默认」会把字体写回**组件首次显示时**的旧值，而不是最新绑定值。
现实触发条件很少（既要设过组件字体、又要在同一次会话里改 CI 主界面字体），所以列为低危，但确实存在。

### R-4（低）WebView2 探测结果失败后缓存到进程结束

`WebView2Availability.IsAvailable` 是 `Lazy`（`Services/WebView2Availability.cs:32-46`），
注释说明是刻意（每次切背景读注册表/起 COM 太浪费）。代价：用户**运行中**安装 WebView2 运行时，
要重启 CI 才能用网页背景；设置页提示文案没提这一点。

### R-5（低）贴纸的 z-order 不可控

所有贴纸实例都塞进同一个 `Panel`（`Views/ClockSurface.axaml:217`），实例顺序即绘制顺序
（`ClockSurface.axaml.cs:449-508` 按 `ImageInstances` 顺序建壳），设置里没有「置顶/置底」。
两个贴纸重叠时，谁盖谁由列表顺序决定；改动列表（增删/重排）会改变遮挡关系，且不可见地发生。

### R-6（低）文字材质在开启时的量测开销

`UpdatePlates` 在每次 `LayoutUpdated` 都对树里每个 `TextBlock` new 一个 `FormattedText`
（`Views/TextMaterialLayer.cs:110-186`，`MeasureText` 在 `:163-186`）。计数片段/音量档位/预警条目
这类模板会反复重建文字块，材质开启时可能成为每秒布局的固定开销。目前用「外框没变就不 `InvalidateVisual`」
（`:152-160`）挡住重绘，但没挡住 `FormattedText` 构造。默认 `TextMaterial = 0` 时不创建这一层。

### R-7（低）`AboutPopupWindow` 的明暗只对「自定义图片」跟背景走

`ShowAboutPopup` 里只有 `BackgroundKind.CustomImage` 会用背景图明暗决定弹窗明暗，
壁纸/纯色/模糊/网页一律跟随界面主题（`Views/ClockSurface.axaml.cs:1215-1219`）。
「亮壁纸 + 深色界面」下弹窗仍是深色方片。

### R-8（低）贴纸实例 id 不防重

`ImageInstance.Id` 只做字符清洗、不查重（`Models/ImageInstance.cs:48-55`）；布局字典键是 `image:<id>`，
重复 id 会让两个实例读写同一份 `ComponentLayout`。自动生成用 8 位随机十六进制（`:18`），
碰撞概率极低；风险主要来自用户手工编辑 `Settings.json`。

## 6. 存储 / 兼容性 / 构建层风险

### 6.1 设置文件没有整体版本号，只有「迁移版本号」

迁移靠三个独立计数器：`ComponentVisibilityMigrationVersion`、`BackgroundDimMigrationVersion`、
`StickerMigrationVersion`（`PluginSettings.cs:977-1004, 336`），外加 `AppliedPaletteVariant = -1`
识别「还没进过主题系统」（`:177`）。没有整体 schema 版本：以后加迁移只能继续加计数器；
某个迁移写坏后无法回滚（版本号已置 1）。当前三个迁移都有「只跑一次 + 不覆盖用户值」的保护。

### 6.2 一键重置不是「恢复成新装状态」

`ResetAllToDefaults` 显式跳过 `ComponentLayouts`、`AdjustingLayout`、`AppliedPaletteVariant`
和三个迁移版本号（`PluginSettings.cs:934-971`）。语义是对的（否则重置后再重启会重跑迁移、
把用户关掉的组件又打开），但「重置」不等于「新装」：迁移版本号保留。

### 6.3 启动加载仍同步；损坏配置会被当成「老用户配置」迁移

`Plugin.Initialize` 同步 `LoadConfig`（`Plugin.cs:63`）。若 `Settings.json` 损坏但文件存在，
后续会走「`File.Exists` 为真 → 补默认压暗 / 迁移主题」分支（`Plugin.cs:76-88`），
等于把一份全新设置当老配置迁移一次。影响很小（迁移本身保守/幂等），但属边界情况未验证。

### 6.4 换行符 / 编码

仓库既有文件混用 CRLF（如 CI 生成的 `cipx/checksums.md` 带 CRLF）与源码文件的 LF。
`.analysis/` 文档写入为 **LF**。若要做「整文件 diff 干净」的提交，需按仓库习惯统一换行符；本次未处理。

### 6.5 仓库里存在构建残留目录

`obj/cswin32probe/`、`obj/probe-bg/`、`obj/verify/` 是调试/验证用的临时工程（含生成的 P/Invoke 源码），
不在源码清单里、也不参与编译。打包不受影响（cipx 只从 `bin/Release` 取）。
