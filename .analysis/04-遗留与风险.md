## 2. 设计上的近似（不是缺陷，但别误解）

### 2.1 文字材质 = 字形填充的近似，不是逐像素折射

材质改的是**文字自己的 `Foreground` 与 `Effect`**（`Views/TextMaterialLayer.cs:151-183`）：
磨砂 = 原色纵向半透明渐变 + `BlurEffect` 0.8；液态玻璃 = 白高光→原色→更透的三段渐变 + 字下半透明投影。
它**不读取背景像素**、也**不产生视觉节点/薄片**（`:20-28`）。
所以「玻璃感」来自渐变 + 小半径模糊/投影的视觉近似，**不是**对字后背景的真实模糊/折射。
DWM 原生透明（`BackgroundKind.NativeBlur`）只在底层提供被模糊过的背景，材质本身与之无关（`:13-18`）。

### 2.2 背景「实时模糊」是 DWM 模糊窗口背后，不是自绘一层模糊

`BackgroundKind.NativeBlur` 下背景层什么都不画（`BackgroundLayer.axaml.cs:517-531`），
模糊来自未公开 API `SetWindowCompositionAttribute`（`NativeBlur.cs:62-82`）。
因此不支持「只在某一小块区域模糊」。

### 2.3 主题「自动」档的方向是反的，这是故意的

`backgroundIsDark ? 明亮 : 黑暗`（`Models/ClockTheme.cs:183-185`）——亮图配白字；理由见 `:15-21`。

### 2.4 强调色只在「用户没改过进度条色」时接管

判据是「当前值等于该调色板默认值」（`ClockThemeApplier.cs:124-137`）。用户改过进度条色后，
即使打开「跟随 ClassIsland」也不会变强调色——设计意图（用户优先）。

### 2.5 高 DPI 下的单位混用是刻意的

- WebView2 `Bounds` 要物理像素、`ClientSize` 是 DIP，所以乘 `RenderScaling` 并设 `RasterizationScale`
  （`WebViewHost.cs:120-142`、`WebBackgroundWindow.axaml.cs:94-105`）；
- 壁纸解码宽度用屏幕**物理**宽（`BackgroundLayer.axaml.cs:624-633`），预览用**逻辑**宽
  （`SettingsPage.axaml.cs:177-203`）。

### 2.6 本地网页是「引用路径」，不是「导入资源」

`BackgroundWebFile` 存**绝对路径**、不复制 html（`Models/PluginSettings.cs:413-424`）：
页面要带同目录的 css/js/图片，只搬 html 会变空白；代价是换机器/挪目录后失效（属设计取舍）。

## 4. 仍未修的风险（按对用户的影响排序）

### R-1（中高）多屏 / 非主屏下，开屏截图与壁纸解码仍取主屏

- 截图用 `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 并 `BitBlt` 屏幕 DC `(0,0)`
  （`Services/ScreenCaptureService.cs:49-104`），拿到的是**主屏**尺寸与主屏画面。
- 壁纸解码宽度取 `Screens.Primary`（`Views/BackgroundLayer.axaml.cs:624-633`，兜底 1920）。
- 设置页预览用「窗口所在那块屏」（`SettingsPage.axaml.cs:177-203`）。

**后果**：大屏开在副屏（分辨率/缩放不同）时，开屏过渡垫底的是主屏截图，壁纸按主屏宽解码导致
模糊半径换算偏差、清晰度不匹配。不影响功能正确性。修法（未实施）：改用 `MonitorFromWindow` 的显示器矩形。

### R-2（中）强调色资源键仍是「按 FluentAvalonia 猜的」

`CiThemeReader` 的 5 个候选键（`Helpers/CiThemeReader.cs:25-32`）没有 CI 官方 API 背书。
CI 换资源命名后表现是**静默读不到 → 回退主题自带色**（不崩不报错，但用户会觉得「跟随没效果」）。

### R-3（中低）组件字体恢复用的是「首次快照」

`ComponentHost` 第一次看到某 `TextBlock` 时记字体快照（`Views/ComponentHost.cs:271-279`），
改回默认/离开可视树时无条件写回（`:317-336`）。**极端路径**：快照之后该文字块绑定值又变了
（如 CI 主界面字体被改），恢复会写回**首次显示时**的旧值。触发条件少，列为低危但确实存在。

### R-4（中低）文字材质只处理纯色文字，且每次布局都遍历文字块

- 原 `Foreground` 不是纯色的文字块会被**跳过**（`Views/TextMaterialLayer.cs:144-145`），
  所以渐变/图片画刷的文字（目前没有，但以后若加）不会套材质。
- `AttachSource` 挂 `LayoutUpdated`，每次布局都 `GetVisualDescendants().OfType<TextBlock>()` 走一遍
  （`:101-121`），命中已是自己画刷时直接跳过、不分配（`:126-128`），但遍历本身随文字块数线性增长。
  默认 `TextMaterial = 0` 时连对象都不建（`ComponentHost.cs:346-358`），只影响开了材质的组件。

### R-5（低）WebView2 探测结果失败后缓存到进程结束

`WebView2Availability.IsAvailable` 是 `Lazy`（`Services/WebView2Availability.cs:32-46`），
刻意如此（每次切背景读注册表/起 COM 太浪费）。代价：运行中安装运行时需重启 CI；提示文案没提这一点。

### R-6（低）贴纸的 z-order 不可控

所有贴纸实例塞进同一个 `Panel`（`Views/ClockSurface.axaml:217`），实例顺序即绘制顺序
（`ClockSurface.axaml.cs:437-495` 按 `ImageInstances` 顺序建壳），设置里没有「置顶/置底」。
两个贴纸重叠时谁盖谁由列表顺序决定，增删/重排会不可见地改变遮挡关系。

### R-7（低）本地 HTML 背景的 file:// 边界

- 页面里的 css/js/图片必须与 html **同目录或子目录**并用相对路径（`BackgroundExtrasPanel.axaml.cs:120-122` 已提示）；
  跨盘符/绝对路径引用、`file://` 被安全策略禁用、超长路径（>MAX_PATH）都可能让页面空白。
- 文件被挪走/删掉后不会报错，只静默回退纯色（`WebBackgroundService.cs:384-406` 里 `File.Exists` 失败即跳过）；
  设置页摘要会显示文件状态，但大屏侧没有兜底提示。
- 存绝对路径 → 换机器/换用户目录后失效（设计取舍，见 §2.6）。

### R-8（低）`AboutPopupWindow` 的明暗只对「自定义图片」跟背景走

`ShowAboutPopup` 里只有 `BackgroundKind.CustomImage` 会用背景图明暗决定弹窗明暗，
壁纸/纯色/模糊/网页一律跟随界面主题（`Views/ClockSurface.axaml.cs:1193-1207`）。

## 6. 存储 / 兼容性 / 构建层风险

### 6.1 四个迁移版本号，仍无整体 schema 版本

`ComponentVisibilityMigrationVersion`（`:992`）、`BackgroundDimMigrationVersion`（`:1005`）、
`StickerMigrationVersion`（`:336`）、`ComponentDefaultsMigrationVersion`（`:1021`），
外加 `AppliedPaletteVariant = -1` 识别「还没进过主题系统」（`:177`）。没有整体版本号：
以后加迁移只能继续加计数器；某个迁移写坏后无法回滚（版本号已置 1）。当前四个迁移都有
「只跑一次 + 不覆盖用户之后的手动修改」的保护。

### 6.2 一键重置不是「恢复成新装状态」

`ResetAllToDefaults` 跳过 `ComponentLayouts`、`AdjustingLayout`、`AppliedPaletteVariant` 与四个迁移版本号
（`Models/PluginSettings.cs:947, 966-970`）。语义是对的（否则重置后重启会重跑迁移），但「重置」≠「新装」。

### 6.3 启动加载仍同步；损坏配置会被当成「老用户配置」迁移

`Plugin.Initialize` 同步 `LoadConfig`（`Plugin.cs:63`）。若 `Settings.json` 损坏但文件存在，
后续会走「`File.Exists` 为真 → 补默认压暗 / 迁移主题」分支（`Plugin.cs:79-91`），
等于把一份全新设置当老配置迁移一次。影响很小，但属边界情况未验证。

### 6.4 默认隐藏迁移对老用户是「强制关一次」

`MigrateOverlappingComponentDefaults` 会把 6 个组件对老配置**无条件关掉**（`PluginSettings.cs:1035-1047`）。
这是用户验收时明确要求的（截图里那块与 CI 重合）；但如果某个老用户恰好一直在用这些组件，
升级后会「东西不见了」，需要自己到组件页加回。README 已说明默认隐藏与可恢复（`README.md:13`）。

### 6.5 换行符 / 编码

仓库既有文件混用 CRLF（CI 生成的 `cipx/checksums.md`）与源码的 LF；`.analysis/` 文档写入为 **LF**。
若要做「整文件 diff 干净」的提交，需按仓库习惯统一换行符；本次未处理。

### 6.6 仓库里存在构建残留目录

`obj/cswin32probe/`、`obj/probe-bg/`、`obj/verify/` 是调试/验证用的临时工程，不在源码清单、不参与编译；
打包只从 `bin/Release` 取，不受影响。

## 8. 结论一句话

验收反馈把「材质不是字、图片有两个入口、重合信息没藏全、网页背景只能填网址」这四件用户直接抱怨的事
都改到了；代码的回退路径仍然完整。剩下的风险依旧是**多屏取屏（R-1）**和
**所有依赖宿主/系统/显卡的行为都还没真机验证**；另外文字材质是字形填充的近似，不要期待逐像素玻璃折射。
